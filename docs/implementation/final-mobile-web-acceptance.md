3. 群聊将未入库 outbox 消息传给 `mark_space_read_through`，真实返回 `P0001 message_not_in_space`。主集成改为只标记最新已发送消息；复测不再出现 400。
4. 群建议和行动卡新增账号/空间/权限/忘记失效屏障，迟到请求不能恢复旧结果。3 套卡片测试共 8 项通过。
5. 群页旧标题硬编码“关系空间”，主集成已改为服务端读取真实群名；最新工作台及群页可辨认实际群。

## 旧管家确认实现及接口证据

- 新迁移 `016_steward_confirmation` 保存私人代发预览与独立幂等决定，绑定本人、异宠、steward/legacy 本人来源、正文摘要、目标群、原文、版本、加入时间及 48 小时有效期。旧客户端可以得到安全的待确认说明，不收到可执行 agent request ID。
- `steward-actions` 的 `confirm` 在同一数据库事务检查来源排除、正文变动、账号删除标记、权限、加入时间、版本与有效期，再创建兼容的 agent request、精确消息和最终回执；不依赖 AI 或 App 持续打开。`dismiss` 只取消私人预览。重复请求不得修改动作或版本，确认重试不重复消息。
- 消息使用真实 `delegation_confirmed_at/by` 署名；历史无确认记录的消息继续标识为历史记录。源忘记隐藏卡片，源删除级联私人预览和决定；已发群消息保留共享记录。
- 私人旧路由直接写可执行代发请求及后续消息均由新数据库 guard 拒绝。确认标记不能借普通消息写入或更新伪造。
- 管家查询仅接受原文明确群名或已明确传入的单群上下文；无群、同名歧义、多群含混均追问。模型选择不能补足用户未指定的群。管家载荷去掉私人 thread 与私人性格摘要，提交前重检群权限及本人来源。
- 旧私人群任务/计划/日程/群提醒不再自动写旧提案，转到新版陪伴的事项确认流程；个人提醒转到新版提醒流程。新版 `AgentWorkbench` 同样复用 `WorkEditor` 和事项详情，保留明确群 ID、完整说明，日期留空；群提醒先选择共同安排或本人提醒。旧后端与历史请求仍保留兼容，不批量转换成新事项。
- 工作台逐字代发通过同一 `steward-actions` 的 `prepare` 事务生成本人 steward 来源及私人预览，完全不调用模型；同 ID 不能替换群或原文，失败不遗留单独来源行。随后仍走同一确认卡及原确认事务。
- `test-steward-confirmation.mjs`：**40 项真实 Auth/RLS/RPC/Edge/helper 断言通过**。覆盖 preview 零外发、逐字确认、恢复/重试、取消竞争、越权、版本、legacy、宠消息/陪伴来源拒绝、忘记/改写/删除、过期、离群再加入、注销、旧写绕过阻断、单群模型载荷，以及工作台来源与请求绑定。
- `StewardActionCard.test.tsx`：**3 项通过**，验证显示预览不执行、网络失败同 ID 重试、忘记拒绝迟到载入、账号和权限变化清空旧卡。
- `AgentWorkbenchRouting.test.tsx`：**6 项通过**，覆盖三个事项入口的群和描述保留、默认无日期/不写旧请求、提醒选择、代发仅预览及保留只读群查询。
