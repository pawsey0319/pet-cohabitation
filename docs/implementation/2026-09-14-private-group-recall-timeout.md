# 私聊查询群消息超时修复（2026-09-14）

## 问题与原因

用户在异宠中询问某个群说了什么时，出现“回答超时中断”。仅查询运行状态、错误码和耗时确认：实际失败属于消息管家 `steward` 路径，文本请求在 101,845 ms 后记录 `text_model_timeout`；没有读取用户的原问题或私人聊天正文。

陪伴和管家的私人群消息汇总仍使用普通文本配置，未使用此前只为群内 @ 设置的低推理量参数。原适配器的网络重试和结构重试各自启动超时，等待可能叠加至约两分钟。陪伴端连接中断后还会直接显示失败，未核对服务端是否已经提交答案。

## 实现

- 增加可选 `RECALL_TEXT_MODEL`，只用于两个私聊入口的群消息汇总；未设置时兼容原 `TEXT_MODEL`。云端配置为同一基础模型的 `glm-5.3(low)` 路线，普通陪伴、群内回复与办事配置保持不变。模型运行记录保存实际选择值。
- 群汇总生成与其网络、结构、管家空泛回答重试共用 45 秒绝对截止；响应正文读取超时也归一成明确错误。45 秒是**生成阶段**预算，不包含检索、鉴权和数据库提交，不承诺用户总等待时间固定。
- 检索按时间与 ID 游标分页，限定查询开始时刻；最近消息最多扫描 200 条，历史/主题最多 4,000 条。模型消息总量最多 12,000 个 UTF-16 单位，单条正文最多 1,000，附实际使用范围和截短说明。来源仅对应实际用于回答的消息。
- 普通汇总问句不误触深度历史扫描。保留群范围、加入时间、删除状态和发言者归一；最终提交继续检查实际消息及成员权限。游标和时间上界不等同数据库快照。
- 兜底改为有说明的原话摘录，总长度不超过 1,200，避免再次触发回复长度错误；它不冒充模型汇总或完整群记录。
- 客户端仅在传输失败时，按原请求只读核对已提交结果，最多 30 秒；明确的服务端业务失败直接显示原因。恢复不会再次调用聊天或任务接口。主动停止、账号变化、记忆版本、话题、来源排除与取消状态继续阻止旧答案返回。
- 晚到的成功回复会清理对应失败队列项并继续后续问题，保留发送期间新输入的草稿。原请求 ID 重试规则保持。

本轮没有新增迁移、重置数据库、改动已有记忆、替换头像或背景。

## 验证与阶段性结果

使用两名新建合成用户、一个临时群及 24 条合成消息，验证两种入口；加入前的标记消息不能进入回答来源。每次验证均精确清理本轮账户和群。

这些是少量样例，不是 P50/P95、固定速度或长期可靠性承诺。首轮自动化检查验证传输、来源与去重；人工复核另发现一条陪伴汇总把带水成员乙写成甲，已增加完整发言者名称核对要求，最终质量复测另行记录，不能把首轮自动化通过等同全部语义正确。

最终全量 Jest 72 套 / 545 项、TypeScript 检查通过。Grok 意见处理后的 Deno 25 项覆盖截止、重试、来源范围、上下文上限与模型配置隔离。真实本机 HTTP 测试确认 200 / 400 / 503 响应在正文卡住时按截止停止；真实 helper 的合成依赖测试覆盖生成期间离群、停止、排除来源及长度兜底。单元测试不能替代真实数据库和手机验收。

最终 pet-chat v59 发布后的同题汇总：陪伴 **10.853 秒**、消息管家 **7.977 秒**。两条回复均正确注明合成查询乙负责带水，保留雨天、交通及午餐尚未决定的区别。该次恢复接口通过真实云端 Auth/RLS 验证：本人能读取同一请求、原问题及关联答案；另一合成账号对同一组精确 ID 全部读不到。群汇总只有阶段与最终回复时，可以没有临时 stream 行；验收用 accepted 事件的当时 revision 校验当前状态，不伪造流式记录。此前一次验收脚本错误地强求 stream 行，已修正测试条件并重测，原失败证据保留。

## Grok 独立意见与处理

按用户本次指定，仅调用一次 `grok-4.6-high`，网关实际返回 `grok-4.6-build`，正常结束。Grok 未发现本轮权限或恢复重复执行的安全阻断项，但建议将管家真实超时也改成原话摘录，并将此列为正确性阻断。主负责人未将该意见等同必须修改的产品合同：真实模型失败仍需保留标准错误、失败运行记录和原请求重试，不能用摘录掩盖模型汇总失败。

已采纳的补强：单次群汇总可使用剩余的完整 45 秒预算，避免在 30 秒人为截断再调用模型；普通未设截止的请求仍保持 30 秒。有效但空泛的陪伴输出改用明确标注的原话摘录，不新增模型调用。管家若已耗尽总预算，不再启动第二次语义生成；仍在失败或返回前保留来源和权限复核。新增测试验证真实超时不会被伪装成功、截止后不再调用以及停止优先于摘录。

Grok 对全局 `reasoning_effort: low` 的担忧不是本次新增行为；原适配器已有该字段，未更改其他模型调用合同。以上少量补强在 Grok 快照之后完成，经主负责人测试及真实云端复测，没有声称 Grok 再看过最终每个字节。
