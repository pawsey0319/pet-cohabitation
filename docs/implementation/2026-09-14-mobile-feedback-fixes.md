## 透明效果使用和质量边界

新版陪伴本体附近的“透明效果”可打开原图对照和浅/深底预览。点击“使用此透明效果”后才替换本体，随时可以恢复原图。已经生成不等于已经应用。

实际毛绒样例恢复了此前丢失的身体、双臂、双脚与蝴蝶结；输出原始 RGB 完全一致，没有棋盘格假透明。深色底放大观察仍有原 JPEG 边缘色污染，不能据这个样例宣布所有毛发、半透明材料和多附肢形象质量通过。默认维持本人预览确认，效果不好保留原图；未知图片不自动批准。

透明 worker 的限定凭据由 Windows DPAPI 加密保存在本账号 LocalAppData，云端只授予领取和提交授权图片任务的能力，不使用 service role。`scripts/start-pet-transparent-worker.ps1` 校验固定模型后隐藏启动，并核对既有进程避免重复启动。正常 AI 重启入口会尝试恢复它，`CheckOnly` 不启动进程。试用期仍依赖这台电脑在线；生成完的资源持久保存在云端。Python 环境/模型当前位于已验证的本机临时目录，尚未部署成独立常驻云端服务或系统开机服务。

## Grok 复查的处理

本次使用用户选择“4.6”对应已确认完整 ID `grok-4.6-high`；网关返回 `grok-4.6-build`。仅一次调用，独立意见不替代源码和实际测试。

- 采纳：尽早发布服务端选定的回复对象，包含空数组。新增慢观察授权与暂停宠场景，回复等待及时消失，同时保留已授权观察。
- 未采纳“去掉所有失败 job”：实际聊天行仅对 queued/running 显示进度，失败记录用于明确重试，Grok 缺少调用方上下文。
- 客户端兼容的呼唤推断由服务端回复对象覆盖，不允许客户端猜测扩大权限。
- 未复现坏缓存详情崩溃：详情加载已有 try/catch；补充损坏缓存 + 深链的实际页面检查。不能通过任意刷新失败就清空草稿来修复猜测问题。
- 未复现旧路由返回循环：已安装 Expo Redirect 使用 replace；实际旧深链、返回聊天和浏览器返回验证通过。
- 透明标记只改变边框/裁切样式，不替换图片来源；实际批准接口和迟到批准保护已在云端验证。

复查时提供的是代码快照。其后最小补强由本地测试和主负责人验收，没有声称 Grok 又检查了最终每个字节。
