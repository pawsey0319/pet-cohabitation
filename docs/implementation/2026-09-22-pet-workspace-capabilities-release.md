# 2026-09-22 异宠工作区与能力授权交付

状态：两批 Android 1.0.9 OTA 已发布并校验远端资源，兼容数据库及服务端已部署。已交付手机验收候选；手机结果、Grok 独立检查和旧计划中的未完成项目均未标记通过。

## 已交付行为

- 陪伴页删除聊天上方的本体、绿色图片和占位；空会话也不插入本体。保留名称、导航、对话、输入、语音和聊天背景。
- 陪伴、记忆、成长、桌宠共用工作区并保留已进入的页面。旧路径转换为工作区的对应模块；切换只更新模块参数。会话缓存合并同一读取，30 秒后后台更新；基础资料、对话/记忆、成长读取分别呈现。草稿、滚动位置及在途回复保留，隐藏页停止对应的语音和资源轮询。退出及账号切换会使旧响应失效。
- 成长/桌宠展示只使用当前确认的透明资源；短暂失败保留仍有效的资源，过期、撤销或形象改变时清除并显示状态。原图仅用于原有比较确认流程，不作为透明资源的失败回退。
- 异宠设置增加“能力与授权”。共享目录 105 项：群公共 4、主人查询 9、需预授权 63、本人确认 11、设备/现有编辑流程 15、暂不可用 3。逐项参数、操作对应和入口见[能力目录](./2026-09-22-pet-capability-catalog.md)。
- 普通写操作默认没有授权。主人选择动作、个人/具体群/具体资料、发起人后确认；默认持续到撤销，不扩展到未来群或新增能力。授权版本和当前成员资格在执行时重查。群观察同意不能代替操作授权。
- 个人陪伴和群聊共用动作规划、授权、执行及回执。模型提出结构化计划，服务端用真实发起人和原业务规则执行；引用、历史消息或检索结果不能赋予权限。本人投票和接受等选择不能交给其他成员代替。
- “通知主人”独立于“替主人表态”。在允许异宠参与的当前群中，其他成员可让异宠 @ 真实主人；写入真实消息、结构化 mention、通知事件和回执，并返回消息定位链接。同发起人/异宠/目标 60 秒冷却，异宠消息不触发新自动链。主人不在群中时明确失败，不跳到其他群或私聊。
- 各步骤保存幂等回执，重试不重复创建消息或事项。多步骤分别记录成功/未授权/冲突/失败；进程或传输中断后保留成功步骤。业务失败回执不会因网络重试被偷偷重新执行，需要新的有效请求。
- 背景/头像生成沿用原配额和队列，并在任务租约/结果写入时重查授权。正式形象、账号删除/私人导出/权限管理仍交本人操作；系统授权仍由当前设备使用者操作。

飞书参考仅用于技能权限与数据权限分开管理，以及通过实际消息接口返回 message ID/mentions 的方式；本项目按用户确认规则默认关闭普通写授权和未来范围继承。[角色权限说明](https://www.feishu.cn/content/ehksl0lb)、[消息技能说明](https://www.feishu.cn/content/mtb6n3ah)，2026-09-22 核对。没有连接飞书账号或向飞书发送消息。

## 手机验收

1. 已装 1.0.9：我的 → 应用更新 → 检查更新 → 下载体验更新 → 重新打开并应用更新。早于 1.0.9 则先从相同入口下载并覆盖安装 build11，再检查体验更新。无需卸载。保存当前输入/发送后再重启。
2. 陪伴页检查本体、绿色方块及原占位都消失；记下本机型号、Android 版本、安装版本和更新信息。第二批的“体验更新”应为 `01a0c86d`（第一批是 `01a0c83c`），并确认“异宠设置 → 能力与授权”可用。
3. 四模块来回切换 20 轮；写一段不发送的草稿，把对话滚到中间，在回复生成中切页。分别检查草稿、滚动位置和回复延续。首次加载单记；用录屏计时统计已加载切换 P95，目标 ≤200 ms。浏览器数据不填入手机结果。
4. 让账号 B 在 Android 登录，A 在另一设备或[网页版](https://pet-cohabitation-public.vercel.app)登录，进入同一测试群并允许 B 的异宠参与。A 从 @ 选择器选 B 的异宠，发送“请 @ 你的主人”。B 检查群里真正的 @、消息定位、前台/后台通知和点击跳转；60 秒内重复应限流。
5. B 在异宠设置 → 能力与授权，搜索“创建目标”，选择“创建目标、阶段或任务 → 授权具体范围 → 个人范围 → 仅本人 → 确认授权”。B 回陪伴页请求“帮我创建个人任务：今晚整理书桌”，到事项页检查实际任务；撤销授权后换一个任务请求，确认没有创建且回执提示未授权。修改事项另授权“修改事项”，不默认继承。
6. 检查后台、锁屏、免打扰和系统通知权限；主人不在群内的场景由受控测试账号准备，不靠同名、文字 @ 或截屏替代真实身份判断。

## 运维与复现

发布命令见 `scripts/pet-workspace-ota.mjs`，已发布源码禁止覆盖；后续改动另建候选。迁移 001–004 已上云，不能原地修改已部署文件。运行 `node scripts/document-pet-capabilities.mjs` 可再生成目录。

若能力执行需紧急停止，将现有 Supabase 项目的 `PET_CAPABILITIES_ENABLED` 设为 false。这会停止新执行链并恢复旧聊天路径；旧的本人确认操作仍遵守原流程，已成功动作不会自动撤回。客户端/数据库向旧版本兼容，不以删除表或回滚业务数据作为停用方式。图片任务另按已有队列状态及授权复核处理。
