# T11 记忆与相处方式实施记录

日期：2026-09-11。执行依据为最终功能完善计划。源码已实现，009 迁移交由整合负责人应用；不代表阶段 2 的真实模型、云端及设备验收已经通过。

## 已实现

- 新增经历、本人介绍的人物和目标阶段，保留本人原文片段、来源消息和表达日期。人物没有群成员绑定字段。愿望、计划、进行中、本人已表达发生分别记录，资料不足不编造回顾。
- 新消息独立登记可恢复提取任务，租约 3 分钟，失败可重试，最多 3 次自动领取。历史回看不会新建提取任务；异宠生成的消息不能成为事实依据。模型建议须经过原话、标签、语义类别和结构校验，提交时重查来源及账号状态。
- 目标阶段明确变化更新当前理解；迟到的旧消息提取不会覆盖较新的阶段。偏好继续复用既有原话依据、权重和排除机制。
- 相处设置包括称呼、长短、建议频率、幽默与轻微吐槽。范围为当前话题、今天和长期；今天按保存的时区当天结束。自动提取默认当前话题，只有明确长期用语才写长期设置。任务捕获原话产生时的话题和时区，迟到任务不能跨话题设置临时要求。
- 陪伴提示接入既有回应风格、当前有效相处设置和最多 5 项相关事实。事实与设置携带来源 ID，供最终回复的记忆版本及来源校验使用。群助手和管家不调用本模块的私人上下文。
- 忘记预览列出原来源、派生回复、衍生事实和关联私人事项；共享事项单列。默认只停用记忆。取消或移除私人事项须逐项携带版本；有下级事项的父项禁止级联删除，需先在事项页处理。
- 纠错把错误来源排除并写入新的本人明确表达；普通变化保留先前真实阶段。排除传播到事实、临时设置、在途提取、接续、回顾、关键词召回和目标下级事项。继续使用既有 `bump_pet_memory_revision` 通知在途回复撤销过期文本。
- 7 天、30 天回顾由用户主动打开，展示真实表达和私人事项状态。接续以当前事项状态和未结束目标为依据，附来源日期；收起记录按账号保存，同一片段不重复出现。
- 陪伴页已接入记忆弹窗、相处设置、回顾、保存轻提示、关键词搜索入口；成长页增加来源明确的回顾。`/pet?messageId=`、`memoryId=` 及兼容 `memory_id=` 通过只读弹窗定位真实来源，服务端 RLS 与客户端 owner/pet 条件同时约束。
- 已接系统语音输入与逐条朗读。识别结果追加到可编辑草稿，不自动发送；语音原生生命周期由 T12 模块负责。修复最新页刷新覆盖历史分页，保留请求队列、SSE 与事项回执卡片。

## 整合合同

- `get_companion_memory_context(target_pet_id, topic_started_at, query_text)` 返回 `{facts, settings, source_ids, revision}`。本人 JWT 只能读自己的异宠；服务角色可指定异宠。整合时将 `source_ids` 合并入最终回复 `context_message_ids`，`facts/settings` 分别传给 `privateCompanion.ts` 的 `lifeFacts/interactionSettings`。
- `search_companion_life_memory(p_owner,p_query,p_from,p_until,p_limit)` 为 service-only，返回与统一搜索一致的 JSON 行，纳入 memory 类型。该函数先检查有效原来源。统一按意思搜索的查询扩展、模型重排与实际来源引用由 T09 的搜索服务整合，不在此函数中推断新事实。
- `memory-evolution` 提供 context、preview_forget、review、continuation、retry 及 manage 写操作。所有写操作携带不可替换内容的 `request_id`；事实编辑须带 `expected_version`，设置须带 `expected_revision`。
- `exportMemoryEvolutionData(client,owner)` 在 `_shared/companionMemoryEvolution.ts` 分页导出新增 5 张表。注销首先调用已有提醒模块的账号 block，再删除账号；本模块领取和最终提交检查同一 block，新表依账号外键级联。客户端没有新增正文持久缓存。
- `companionMemoryTypes.ts` 仅包含纯类型和校验，客户端不导入含 Deno/npm 的服务端文件。

## 按意思搜索补充交付

- `semantic-search` 为本人主动调用的独立接口，输入只有查询词、类型、群、日期和状态；不向模型传入全量资料。扩展至多 3 个短词组，统一关键词 RPC 每组先鉴权召回，合并后至多 60 项候选，重排至多返回 30 项。
- 模型只能返回现有候选键，不能写摘要、创造来源或执行工具。模型生成的搜索内容不写长期记忆，不建设向量库。仍读取现有 `TEXT_*` 配置；单账号每日最多 100 次该搜索以限制服务调用，运行记录仅含状态、模型名和耗时，不记录查询正文。
- 014 新增 service-only `revalidate_search_results`：模型前重新读取候选，模型后再次读取当前权限、原来源排除、状态、日期及实际文本。群成员离开、忘记、内容变化、任务状态变化或删除都会使旧候选失效。返回路由由数据库重新构造，不采用模型路由。
- 界面增加“按意思找”，仅点击后调用；AI 搜索过程中可以立即点击“查找”使用关键词，旧 AI 结果不会覆盖后来的关键词结果。模型失败保留原有关键词结果。账号、范围、离群和忘记事件使进行中的结果失效。
- `scripts/test-semantic-search-sql.mjs` 隔离 SQL 权限/来源/状态/删除回归通过；`semantic-search/semantic.test.ts` 3 项编排测试通过；统一搜索 UI 10 项通过。
