# Android App 内云端更新 · 2026-09-21

用户要求旧 App 直接取得更新，不能把每次找 APK 链接、重新下载安装作为正常交付流程。本次补上该能力；没有新增原生依赖或要求 Google Play。

后续交付更新：已发布 1.0.9（11）手机验收候选，并向 1.0.4–1.0.9 分别更新 APK 元信息。当前收据和手机步骤见 [1.0.9 手机验收记录](./2026-09-21-android-1.0.9-device-acceptance.md)；下文的五个 OTA ID 保留为首次入口上线历史。

## 使用方式

进入“我的 → 应用更新”，检查并下载更新。1.0.4–1.0.7 保留旧版我的页布局，更新面板在页面下方；发现新的原生版本时也会显示可关闭的提示。

- 普通界面、功能修复通过当前运行时的 EAS OTA 下载；用户确认重新打开后生效，不重新安装 APK。
- 新增桌面悬浮等原生能力时，从 App 内“下载并更新”打开官方 APK 下载页面，随后由安卓系统确认覆盖安装。不会静默安装；网页交接成功不被记作已下载或已安装。
- 旧 App 尚未包含本次入口时，先联网打开，让原有 ON_LOAD 更新机制下载入口补丁，再完全退出、重开。首次入口不能凭空出现在已经运行的旧 JS 中。
- 不卸载旧 App。账号、群、头像与背景仍使用既有数据；实际覆盖安装和资料保留需要用户真机验收。

## 实现与约束

客户端为 `src/updates/`，入口在 `app/_layout.tsx`、`app/(tabs)/me.tsx`。

1. 版本来自原生 ExpoApplication；旧环境缺失时使用内置运行时的语义版本。不会用可被 OTA 改写的 expoConfig 版本冒充已安装版本。“我的”底部原来写死的 1.0.5 已修正。
2. 云端原生发布清单位于 `public/releases/android-preview.json`。校验包名、渠道、版本、文件长度、SHA256 元信息及本次审核的 EAS APK 路径；任意其他 EAS 文件不能冒充本 App。实际 APK 哈希、签名和包名由发布前验收脚本核对。
3. 点击下载前重新取清单。只允许升级，不提示同版或降级安装。核对不通过时保留现版。
4. 普通 OTA 由 Expo 原生更新模块验证运行时和资源，客户端额外拒绝缺失或不匹配的运行时；合法回退指令走 SDK 对内置包的处理，不被误判为缺少 manifest。
5. 重复操作共用进行中的请求；请求有超时。失败不显示“已是最新”，迟到检查不能覆盖后一次结果。应用 OTA 需要用户明确操作，不自动打断正在输入或发送。
6. 清单使用 no-store。未知 `/releases/*.json` 返回 404，不落入网页的 index.html。

客户端并不自行下载、校验或安装 APK 文件；它校验已批准的发布元信息后交给浏览器和安卓系统。不能把浏览器已打开、服务端文件可访问或签名静态检查说成手机已更新。

### 中间旧版本兼容依据

1.0.5、1.0.6、1.0.7 的兼容候选以已提交的 `88aaeb0` 为业务基线，仅加入更新模块和入口，使用各 APK 实际的原生版本/运行时（build 6、7、8）。三版 APK 的104项原生 `.so` 逐文件 SHA256 相同；依赖与锁文件相同，系统语音模块同源，不包含1.0.8新增桌宠模块。

另从原始缓存及本任务历史改动恢复12个旧文件，冻结SHA全部一致。1.0.7剩余pet/chat/types三项不能声称逐字恢复；其最后补丁的关键新增行在88aaeb0均保留，未观察到业务回退。它们是正常的兼容更新，不是1.0.4那种逐字保持旧业务的补丁。证据位于 `test-results/legacy-source-recovery/README.md` 和 `test-results/legacy-update-inventory/fallback-native-contract.json`。三版均已分别完成真实导出、发布及全部云端资源核验，最终收据为 `candidate-1.0.x-cloud-verification-theme.json`。

未采纳“关闭 ON_LOAD”的建议：旧版入口本身依赖该原生启动机制，而 Expo 原生层会按运行时选择更新；把 JS 校验看作唯一安全边界不符合实际 SDK。只改 JS 也不能改写旧 APK 的原生配置。保留启动更新，避免切断旧版接收入口的路径。没有把缺少真机证据描述成通过。

## 后续发布规则

- 仅改 JS、样式或业务逻辑时，保持 App 原生版本与运行时不变，发布 OTA；不要为了普通修复反复生成 APK。
- 仅新增或改动原生模块、权限、启动配置时增加原生版本与 versionCode，使用原包名和签名构建。先核验实物 APK，再更新受支持旧运行时中的已批准 APK 元信息和云端清单。
- 新原生能力的 JS 不直接冒充旧运行时。旧运行时补发经过兼容验证的入口；保留原有功能和来源排除保护。
- 每次发布保存准确源码、锁文件、原生配置、导出包、来源映射与哈希，避免只记录脏工作区的 Git 提交号，导致旧版无法复现。
- 更新检查不读私人聊天，既有账号和云端数据不迁移、不重置。本次不新建安装 APK。
