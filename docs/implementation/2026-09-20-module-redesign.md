## 模块归属

| 入口 | 唯一职责与实现 |
|---|---|
| 消息 | 群列表与群聊；搜索、事项、邀请、头像、群权限等进入群工具，由整合负责人实现 |
| 异宠 / 陪伴 | 默认个人对话、接续卡、真实事项及代发回执、查询群聊；保持输入紧跟实际上下文 |
| 异宠 / 记忆 | `/pet-memory`：偏好依据、经历人物、手工记忆、纠正、忘记、来源和重试 |
| 异宠 / 成长 | `/pet-growth`：已发布本体、透明预览确认、真实成长及回顾；性格和关系的独立入口 |
| 异宠 / 桌宠 | `/pet-desktop`：复用 `DesktopPetSettings`，由本机真实能力与授权决定开启状态 |
| 相处设置 | `/pet-settings`：原有称呼/回应方式设置、回答组织偏好、性格、关系与历史入口 |
| 性格变化 | `/pet-personality`：初始底色、当前习惯、跨天学习依据、暂停、恢复、禁用习惯、纠错、忘记及任务重试 |
| 群关系理解 | `/pet-relations?spaceId=…`：本人异宠在指定群的有来源理解与纠正；各群隔离 |
| 群关系授权 | `/pet-relationship-consent?spaceId=…&petId=…`：当前成员给指定异宠独立授权，不要求此异宠归本人所有 |
| 历史对话 | `/pet-history`：分页回看陪伴、早期消息管家及未分类原记录，保留历史代发确认卡，不重新提取记忆 |
| 事项 | 继续复用 `WorkItemsPanel` 和既有唯一详情；群范围链接兼容转到 `/group-items` |
| 我的 | 账号、头像、全局外观背景、通知、导出注销及服务状态；移除重复的相处设置 |

`/pet?section=steward`、旧 `mode=steward` 进入陪伴兼容入口；原始记录可在历史页回看。旧 `/me?pane=reply` 转到相处设置。新页面返回后重新读取陪伴上下文，保持当前话题与未发送草稿。

## 实际接入与连续性

- 性格和关系页面使用 `pet-personality`、`space-relationship-consent` 实际接口。请求前后验证账号；操作携带版本和固定请求 ID，网络结果不明时复用同一请求。不同群之间的迟到授权结果不能覆盖新群。
- 显示公开的初始性格摘要，不暴露内部提示词。失效依据由服务端停用和隐藏原话；主人纠正不冒充全群共同事实。
- 个人记忆仍复用现有仓库和上限。手工修改后返回当前聊天，不创建新话题。原话使用既有权限受控来源弹窗。
- 取消陪伴页内“拖动异宠”控制，改为轻量本体预览及真实桌宠设置入口；成长页展示原本体但不再用页内拖动冒充桌面能力。网页明确提示 Windows 独立程序要求。
- 陪伴输入位于消息滚动区之后。新增尾部锚点：新内容、窄屏和键盘布局改变时接续末尾；用户正在回看旧内容时保留位置。历史分页按钮移至消息之前，不隔开最后回复和输入。
- 原有背景、语音输入、图片附件、请求队列、真实流式、停止/重试、来源排除及新话题确认保留。
- 我的数据导出加入 `exportPendingChatMessages(owner)`，含本机未发群消息。账号退出/注销清理由整合负责人统一接入。
- `Icon` 在网页使用 `aria-hidden`，原生继续使用原生辅助功能属性，修正网页开发时的无效 DOM 属性错误。
