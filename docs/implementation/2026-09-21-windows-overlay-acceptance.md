# Windows 桌宠实际窗口验收

本轮运行真实 Electron 44.4.3、真实云端合成账号和获本人批准的透明形象。鼠标拖动及点击通过 Windows user32 输入，窗口不是网页中的模拟浮层。测试拦截开机启动设置写入，没有安装程序或修改注册表；这不替代安装/卸载、锁屏、多屏及人手体验验收。

## 本轮发现与修复

1. 透明色检查误用 `getBackgroundColor()`：该接口只返回 RGB，不能用于证明 alpha。验收改为检查原生窗口截图的像素透明度，并保留实际截图。
2. 真实置顶失效：`setAlwaysOnTop(true, "floating")` 在这台 Windows 上返回非置顶。Electron 此层级会把窗口放到任务栏 HWND 之后；本机复现中，改为 true + normal 后显示、隐藏恢复均保持置顶且不抢焦点。桌宠与聊天窗统一采用该设置，窗口仍约束在显示器工作区。
3. 拖动位置丢失：画布拖动调用 setBounds，只触发 move，没有触发旧代码监听的 moved。已监听 move 并保留原有 250ms 去抖和按账号加密存储。
4. 测试在窗口加载之前读 URL 会遇到空字符串，现将尚未加载窗口视作 about:blank，继续等待实际页面，不提前通过。
5. 点击穿透测试本身有两处问题：原落点位于底层窗口的原生边缘，改为更大的不可调整尺寸测试窗；原 SetCursorPos 移动不会模拟 Electron 所需的底层鼠标钩子输入，改用带虚拟桌面坐标的真实 mouse_event 移动。输入前核对 Windows 命中的原生句柄属于本次测试，避免向其他应用发送点击。改好测试后原有 pointermove 处理可恢复本体拖动，没有保留曾尝试的鼠标事件修改，也不将该项算作产品缺陷。

官方实现核对：[Electron v44.4.3 Windows 窗口层级处理](https://github.com/electron/electron/blob/v44.4.3/shell/browser/native_window_views.cc)。实际复现记录为 `test-results/desktop-window-layer-probe/report.json`：floating 的 before/shown/restored 均 false，normal 均 true；两个 move 事件、零 moved 事件。

失败记录保留，合成资料清理成功：

- `desktop-overlay-95f4696b-3a0c-4c0a-a13e-242072fabcd6`：透明处理成功，原窗口组合检查失败。
- `desktop-overlay-f5320a03-dcaf-4edd-9a9f-4e40df7b92a5`：置顶、原生透明截图、鼠标拖动、隐藏和托盘恢复通过，但停止后位置恢复失败。
