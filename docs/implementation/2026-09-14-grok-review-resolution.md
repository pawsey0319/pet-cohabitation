## 意见处理

| Grok 意见 | 主负责人核验与处理 |
|---|---|
| 同一来源/版本的新任务会使已确认图失效 | 未复现。003 的 `request_pet_transparent` 在 owner 事务锁内复用 queued/running/uploading/succeeded 任务。新增两个同账号 session 用不同请求 ID 并发请求的真实 Edge/DB 测试，仍只有同一个成功任务且确认图保持可用；不能由 status 的 order/limit 推断此并发能够生成新任务。 |
| 重放旧确认回执会破坏恢复原图 | 未发现当前实现会这样写回。重放返回原操作回执，不重新执行 update；客户端忽略该旧快照、重新读取当前状态。真实接口测试覆盖恢复后重放仍为原图，以及签名过程中恢复、换源、注销。保留稳定的幂等回执合同。 |
| 有子任务的旧父任务可能被恢复重跑 | 采纳更保守的恢复边界。新版 router 已对 succeeded 子任务跳过，并按原 child ID 提交去重，因此“必然重复消息”不成立；但旧来源已有子任务时无需自动重跑整段路由。恢复脚本改为任何状态、有无消息的 reply child 都进入人工核对。 |
| 部分完成的旧任务仍停在 running，仅输出数量 | 采纳。沿用 failed 终态及专用 review error_code，保留原任务 ID、尝试次数和结果，输出可核对的 ID；每类仍最多处理 100 条。手动重试入口同时阻止 review 标记被清除，包括读取后才被标记的并发。 |
| 成功透明图的签名链接过期后不会续期 | 采纳。当前来源的候选/主图以早于 300 秒到期的间隔刷新；后台、离页、账号/来源变化及 Realtime 错误仍使旧展示失效。 |
