## 云端验收结果

三组测试覆盖不同范围，不用合并数字代替完整产品验收。

- **业务接口 41/41**：22 次实际 Edge HTTP，覆盖人类消息事务回执、同 ID 重放及内容冲突、事项创建/修改/完成、旧版私聊 JSON 回放、权限隔离、导出、注销及共享记录处理。两个合成账号和一个合成群完全清理；此组不调用模型。
- **真实模型 11/11**：云端文本健康检查、一次陪伴回复及原请求重放；最终仅一条本人消息、一条异宠回复及一次成功私聊模型记录。第一次回答接口耗时 16,482ms，重放 872ms。这是单个样本，不代表 P50/P95 或长期可用性。图片只验证目录可达，未在此组验证生成质量。
- **实际提醒 21/21**：由部署的接口创建一次性个人提醒，06:28:54 到期，06:29:00.129196 的真实 Cron 创建唯一实例及事件；跨 06:30 周期仍无重复。没有手动调用调度冒充定时触发。账号无设备，状态正确为 `cancelled / no_active_device`，没有发送外部通知；新版注销接口清理完成且 Auth 返回 404。
- **调度运行观察**：4 条每分钟 Cron 各执行 10 次，图片维护执行 2 次，SQL 均成功。新启用时间后 32 个 pg_net 响应均为 HTTP 200，无超时、缺失状态或当前队列积压。该元数据为项目聚合，不能逐条归属到某个函数，也不证明手机已显示通知。

只使用本轮合成账号、来源和数据；日志不记录真实私人正文、图片、密钥或模型回答。

## 排查过程中保留的失败记录

- 首次维护检查对图片生成入口发送了错误的空请求，400 是正确业务行为。数据库尚未切换时恢复对应原函数，修正测试请求后重新完成正式维护与排空。
- 首两次业务 smoke 遇到托管网关的无 Authorization 401 格式与本地 handler 不同。仅调整测试对官方网关实际错误结构的匹配；两次合成账号均已清理，没有修改业务鉴权。
- 首次真实模型检查返回离线。CPA 本机接口实际可用，但旧公网隧道不可达；第一次重连又因代理接管 loopback 导致本机探测失败。给本次启动进程设置 `NO_PROXY=127.0.0.1,localhost,::1` 后建立新隧道并完成云端真实生成。没有更改全局代理设置，也没有将“进程存在”当作连接通过。
