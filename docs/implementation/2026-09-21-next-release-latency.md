## 测量口径

全部使用本轮新建并清理的合成账号/群，或这些测试保存的合成对话。客户端为 Windows 主机，冷启动未受控；连续请求使用相同账号、网络和逐渐增长的对话。每组按最近秩法计算 P50/P95，小样本分位数只描述本次数据。

普通消息 ACK 是请求至持久入库确认。群回复由约 1 秒一次的查询观察到完整消息，不是首 token 或手机渲染时间。陪伴首段只记录非空 `text` 事件，`accepted`、`phase`、`done` 均不计。表内完成时间只纳入成功回复，失败次数另列；不能把超时耗时算成一次成功回复。

## 已复现并修复的格式问题

云端第 4 次个人陪伴请求报 `text_model_invalid_json`。使用其前三轮成功的合成问答和第四个问题做定向重放，业务模型保持 `glm-5.3`；通过已部署模型名的摘要与现有网关目录比对确认，没有替换模型。

旧提示把历史 assistant 回复作为普通文本发送，而当前轮要求 JSON。诊断保存的原始输出确实是普通中文回应。候选修复把历史 assistant 的正文用 `JSON.stringify({content: ...})` 包装成要求的回复格式，保留正文、时间、引号、换行、表情和原有忘记过滤，不补造历史风险或情绪字段。

仅为已完成但 JSON/结构无效的回复增加至多一次同模型重试。重试前清空临时文字并执行调用方已有的版本/租约检查，两次请求共用一个 90 秒上限。停止、忘记、网络错误、截断与提供方过滤不触发格式重试；业务动作和最终提交仍由原请求执行一次。
