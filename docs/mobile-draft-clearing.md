# 异宠发送后输入框残留修复

日期：2026-09-09。

## 问题与处理

原陪伴输入区在 `onSend` 等到整个回答完成、本机草稿删除后才清空。模型等待期间文字一直留在输入框，输入法迟到事件也可能重新写入草稿。重开页面恢复本机草稿时，没有核对同一请求是否已有成功回答。

现在点击发送立即把正文和请求 ID 固定为本次发送副本，并清空可见输入。恢复副本保留到回复提交成功；发送期间输入禁止修改，忽略迟到的输入事件。失败恢复原文，普通重试复用同一请求 ID；来源失效时按已有接口规则生成新请求 ID。

成功后的本机清理异常不再被当作发送失败。恢复草稿时检查当前账号已加载的消息：同一请求已成功或已有关联回复，则清除旧恢复副本，不重新填入。实时同步晚到的成功状态也执行该核对。

消息管家发送期间同步禁用输入。原来的输入框位置、键盘避让和后台记忆机制沿用。

## 验证

- 修复前新增的“发送后立即清空”和“重开时不恢复已完成请求”两项回归测试均失败；修复后通过。
- 陪伴组件 10 项测试通过，涵盖点击发送后等待中的空输入、迟到输入事件、失败恢复、请求 ID 保留、重开、跨账号和已完成草稿排除。
- TypeScript 检查通过。
- 浏览器实际按钮和 Enter 发送均清空，重新加载后仍为空，消息各只有一条；短/长对话、记忆编辑、管家、群聊和主 Agent 布局检查通过。
- 未连接物理安卓输入法，以上不能替代特定手机的输入法验收。
