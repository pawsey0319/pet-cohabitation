# 异宠功能完善执行计划
**版本：最终执行版 · 2026-09-11**

本文合并此前全部确认及最后一轮 21 项选择，替代旧草案中冲突或待定的内容。它是后续开发、验收和发布的执行依据，不代表相关功能已经实现。

## 一、目标、范围与交付顺序

### 1. 产品目标

让异宠成为**有稳定性格、理解用户变化，也能帮助推进事情的个人伙伴**，同时支持朋友、伴侣和家人小群协作。

用户可以在陪伴对话中倾诉、查询、管理记忆、创建事项和安排提醒。异宠先理解当前需要，再使用对应能力。

必须打通两条流程：

- **个人流程：**想法或明确指令 → 讨论与确认 → 目标、阶段和任务 → 提醒 → 完成、延期或放弃 → 有依据的回顾。
- **群协作流程：**群内信息 → 整理建议 → 确认发布 → 相关成员同意 → 负责人接受 → 更新进度 → 完成或验收。

全过程明确区分：**建议、创建、发布、接受、执行和现实完成。**

### 2. 保留的产品基础

- 保留已认可的商务简洁视觉、主题切换和自定义背景。
- 默认进入异宠陪伴；消息管家、成长保留独立入口。
- 陪伴输入框紧跟实际上下文，展开键盘时可见。
- 消息页右上角不恢复通知按钮。
- 复用现有记忆依据、偏好权重、纠错忘记、请求去重、版本校验和图片生成能力。
- 未确认异宠继续采用填写期待、生成、确认流程，不恢复旧版五轮孵化。

### 3. 分阶段交付

| 阶段 | 重要性 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|---|
| **0A：基础体验修复** | 最高 | 群聊加载和发送、启动占位图、上传头像、成长展示清理 | 普通聊天与安卓启动、键盘回归通过 |
| **0B：形象能力补齐** | P0 | AI 头像、群头像拼图、异宠透明本体 | 真实图片链路、权限与视觉验收通过 |
| **1A：个人事项** | P0 | 统一陪伴入口、事项页、目标与任务、个人离线编辑、材料附件 | 个人创建至完成流程通过 |
| **1B：群协作** | P0 | 分工确认、共同决定、进度与验收、授权后的主动整理 | 多账号协作与权限验收通过 |
| **1C：提醒与查询** | P0 | 重复提醒、系统通知、统一关键词搜索、渐进回答与恢复 | 云端调度、安卓通知和完整协作流程通过 |
| **2：记忆与性格** | P1 | 经历和人物、相处设置、忘记传播、接续回顾、按意思搜索、成长时间线 | 记忆准确性、连续性和真实模型评测通过 |
| **3：语音与背景** | P2 | 系统语音输入和朗读、背景管理与原图编辑 | 原生语音、图片编辑与恢复通过 |
| **4：陪伴图片理解** | 后续独立交付 | 发图提问、图片上下文、可确认的图片记忆 | 真实多模态模型评测通过 |

0A 可以先发布；0B 不阻塞已经通过验收的聊天修复。阶段 1 完整通过后开展首轮 7 天试用，阶段 2–4 分批交付。试用发现的严重问题优先修复。

## 二、功能规格

### 1. 群聊加载、发送与持续输入

**解决当前进群慢、普通文字长时间显示发送中的问题。**

- 已访问的群先显示本账号缓存，再同步新消息；首次进入优先加载最近消息。
- Agent 任务、提案和其他辅助信息分别加载，失败时不阻断聊天记录显示。
- 使用 Realtime 增量更新，断线后补同步；合并并发刷新，移除固定每 3 秒全量刷新。
- 消息分页使用时间与 ID 的稳定游标，避免同一时间多条消息漏读。
- 人类消息事务入库成功后，直接根据服务端回执标记“已发送”，不等待 AI 路由或整页刷新。
- AI 的排队、查找、生成、失败状态单独展示。
- 消息入库与后台事件登记保持事务一致，关闭 App 不导致已登记任务丢失。
- 同一请求重试不重复消息；相同请求 ID 不允许替换内容、附件或模式。
- 发送只清空本次提交的草稿，不清除发送过程中继续输入的新文字。
- 陪伴回答期间始终可输入、可继续发送，同一会话按序处理；提供停止当前回答。
- 停止回答不删除已发送消息，也不自动撤销已经创建的事项；已执行操作提供明确取消入口。
- 补齐私聊历史分页，历史未分类记录可以回看，但不批量重新提取记忆。

缓存按账号和会话隔离。退出账号、收到离群或权限撤销信息后，停止展示相关缓存并清理；离线时不能声称已核实最新权限。

### 2. 启动、头像与异宠展示

**启动**

- 配置品牌图标和启动画面，消除当前网格占位图。
- 原生启动、主题恢复、首个页面保持连贯，不闪回旧界面。
- 启动不等待模型健康检查或图片生成。

**个人头像**

- 支持相册上传、裁剪、预览、保存、恢复默认。
- 支持描述生成 AI 头像，生成后由用户预览应用。
- 同步个人页、聊天双方头像、成员列表和提及列表。
- 上传或生成失败保留旧头像；加载失败回退文字占位。

**群头像**

- 默认由成员头像拼图组成，按稳定成员顺序最多显示 9 人。
- 群主可上传自定义群图、恢复默认拼图。
- 成员变化只更新默认拼图，不覆盖自定义群图。
- 首版沿用群主、成员两种角色，不增加管理员体系。

**异宠本体**

- 成长页去掉明显底板、图片边框及“它不会再回到初始捏宠”等技术性说明。
- 使用透明 PNG 展示异宠本体，保留原始资产及恢复入口。
- 透明图属于展示衍生资源，不增加生命阶段、不形成成长事件。
- 首版使用独立图片处理 worker，采用 `rembg` 并明确指定 `isnet-general-use`，生成主体遮罩并合成透明图；固定依赖与模型文件校验值，不依赖库的默认模型选择。[rembg 项目说明](https://github.com/danielgatis/rembg)
- worker 从云端领取获授权的图片任务；试用期可以运行在现有电脑上，处理完成的图片持续保存在云端。
- 不使用生成式重绘替代背景去除。主体结构、颜色和身份必须保持，失败保留原图。
- 验收覆盖毛发、细小装饰、多附肢和半透明部位；棋盘格假透明、缺肢、明显脏边均不通过。

AI 头像与背景设计共用现有个人图片额度，初始保持每日 12 次；重试按任务去重。系统透明本体修复不占用户主动设计额度。

### 3. 统一陪伴入口与事项页

底部导航调整为：**消息、异宠、事项、我的**，默认仍进入异宠。

**陪伴入口**

- 直接支持聊天、查群消息、查事项、创建和管理个人事项、记忆操作。
- 信息完整的明确个人指令可直接执行，成功后展示真实回执和编辑、取消入口。
- 随口表达愿望先自然回应，合适时提出建议；用户接受后才创建计划。
- 复杂计划采用“聊天追问＋可编辑卡片”，一次优先追问一个阻碍执行的缺项。
- 混合情绪与办事表达同时处理。例如“累死了，明早九点提醒我交材料”：简短关心，同时创建提醒。
- 群范围沿用明确上下文；没有依据时询问群名，不默认扫描所有群。

**事项页**

- 默认展示待处理，支持个人、群事项、目标和已结束筛选。
- 待本人确认和今天到期事项优先。
- 目标下有阶段，阶段下有任务；独立任务不强制归入目标。
- 日期和提醒均可为空，不擅自给任务安排截止时间。
- 支持说明、链接、图片、来源消息；完成时可附文字或图片说明。
- 首版不支持 PDF 和任意文件附件，也不自动抓取链接全文。
- 聊天卡片、群卡片、事项详情引用同一份数据，不维护独立进度副本。
- 目标进度依据真实任务完成数量；取消任务单独记录，不能通过取消未完成任务使目标自动完成。

### 4. 群协作、署名与确认

| 行为 | 规则 |
|---|---|
| 本人让异宠发布安排 | 先预览外发内容，确认后发布；署名“异宠代本人发布”，注明本人已确认 |
| 分配任务 | 负责人接受后才形成承诺；拒绝后回到发起人处理 |
| 负责人更新进度 | 可以自行更新进度、说明和完成结果 |
| 修改截止时间、负责人、交付要求 | 形成新约定版本，由发起人及受影响成员确认 |
| 安排具体成员的共同时间 | 被安排成员全部同意 |
| 不强加个人责任的普通方案 | 按发布时投票成员快照过半数通过 |
| 任务完成 | 默认负责人自报完成；创建时可开启发起人验收 |
| 成员未回应 | 保持待确认，沉默不算同意 |
| 群进度变化 | 更新原卡片；关键节点通知，不为每次字段变化刷群 |

任务状态采用：**待接受、待开始、进行中、待验收、已完成、已取消**。逾期为附加时间标记，不等同失败。

确认版本只绑定约定内容；普通进度更新不要求重新同意。默认提案有效期 48 小时，早于事项发生时间，发布前可编辑。

相关成员离群使未完成确认失效，提示重新分配，不自动缩小人数后通过。已接受事项保留记录；新成员不自动继承责任。

### 5. 群助手主动整理

- 增加独立“群待办识别”授权，全员同意后生效，不复用个人记忆或原有观察授权。
- 仅分析授权生效后的群消息；新成员加入后暂停，重新取得全员授权。
- 任一成员撤回后停止后续分析，迟到任务提交前重新检查授权版本。
- 统一由群助手提出主动建议，避免多只异宠重复插话；明确点名某只异宠仍由其回应。
- 以一段讨论为单位合并：默认连续 3 分钟没有新消息后处理该批消息，不在持续讨论中反复插入建议。
- 只提取有原话依据的行动、安排和责任线索；假设、玩笑、已经否定的计划不形成待办。
- 群内先显示轻提示，如“发现 2 件可能要跟进的事”；展开后查看建议和来源。
- 任一成员可接受、修改并作为发起人确认发布；未接受前不创建正式任务。
- “收起”只影响本人。相同来源和事项去重，已有建议更新原卡，不重新发送。
- 主动建议默认不产生系统推送；正式事项需要本人确认时才按通知规则提醒。
- 原授权失效时，未接受建议停止继续使用相关来源；已确认事项按正常协作规则管理。

### 6. 提醒、通知与离线

**重复规则**

支持一次性、每天、每周选定日、工作日、每月指定日、自定义间隔、结束日期和跳过本次。

工程默认：

- 工作日为周一至周五，界面说明不包含法定节假日、调休。
- 每月不存在指定日期时落在当月最后一天，并在设置中明示。
- 保存时区和当地时间规则；切换设备时区不悄悄移动既定安排。
- 修改重复提醒时支持本次、之后各次、整个系列。
- 任务截止时间与提醒时间分开；未指定提醒时间时不擅自创建。
- 过期不循环催促；下次相关重逢可提一次，提供完成、延期、放弃。

**通知默认**

- 普通群消息、@我、需要本人确认的事项和自己设定的提醒默认通知。
- 可逐群静音；已有用户明确设置不被迁移覆盖。
- 默认 23:00–08:00 聊天不响、不震，可修改时段。
- 主动设在免打扰时段的提醒，保存时提示后仍按提醒设置执行；遵守手机系统权限与勿扰设置。
- 当前正在查看的会话不重复响铃。
- 锁屏标题、正文默认隐藏具体内容；用户主动开启预览后才显示。
- 点击通知进入对应消息或事项；对象已取消、已删除或无权限时说明最新状态。

**可靠性**

- 调度与投递在云端运行，独立于 CPA、隧道和 App 是否打开。
- 沿用 `expo-notifications` 与 Expo Push，补齐设备注册、注销解绑、FCM 配置、逐设备状态、重试和回执查询。
- 推送票据与回执不能证明手机已经展示，必须有安卓真机验收记录。[Expo 投递说明](https://docs.expo.dev/push-notifications/faq/)
- 无权限、无有效设备、通道失败分别展示状态，不显示虚假的“已送达”。
- 目标试用设备实际收不到推送时，提醒能力不得标为通过，也不能要求参与者连接开发者局域网来替代验收。

**离线**

- AI 离线但手机有网：群聊、事项查看与编辑、完成操作、云端提醒正常工作。
- 手机断网：查看缓存；个人事项可离线新建、修改和完成，显示待同步。
- 群投票、接受任务、修改共同安排需联网。
- 冲突保留本地修改供用户处理，不以旧数据覆盖新版本。
- 离线修改提醒在同步成功前不改变云端原提醒，界面明确显示尚未生效。

### 7. 记忆、性格、接续与成长

**记忆基础**

继续使用“表达依据 → 当前理解 → 本轮相关记忆”。

- 手工记忆维持 20 条、每条 400 字，自动依据独立分页。
- 偏好权重保持时间 50%、频次 30%、强度 20%；30 天半衰期、近 90 天统计、同对象同日一次、5 天达到频次上限。
- 状态、场景和明确否定先于分数；每轮最多选取 5 项相关偏好。
- 事实、人物和已经发生的经历不通过偏好分数判断真假。

**新增积累**

- 记录本人明确表达的经历、目标和本人介绍的重要人物。
- 人物默认是私人记录，同名不自动绑定群成员。
- 区分愿望、计划、进行中和已发生，模型生成内容不能反过来充当事实证据。
- 自动记忆成功后在消息旁轻提示，展开可看内容、依据与纠正入口。
- 提取失败不阻断聊天，可重试，同来源不重复累计。

**变化、纠错与忘记**

- 明确变化直接更新，不开启新话题。
- 纠错使错误依据失效，不能将其描述为真实过去。
- 忘记先列出对象、来源、派生内容和关联私人事项；默认停用记忆，可选择取消或移除关联私人事项。
- 共享群事项单独处理，不因个人忘记而静默删除。
- 排除传播到接续、回顾、成长时间线、性格习惯来源、关键词搜索、按意思搜索及在途回复。
- 已忘记内容默认不进入统一搜索；原始聊天在原会话仍可回看，回看不触发重新提取。
- 用户后来新的明确表达可形成新依据，但不能从被停用的原来源恢复。

**相处方式与性格**

- 保持稳定性格底色，逐渐形成表达习惯和细节。
- 支持称呼、回应长度、建议频率、幽默与轻微吐槽；先修复现有回应风格未接入陪伴提示的问题。
- “今天”有效至当前时区当天结束；“这次”仅限当前话题；“以后都”修改长期设置。
- 未明确长期的临时要求默认作用于当前话题，可在轻提示中查看和调整。
- 用户明确不喜欢的相处方式优先于自动积累的习惯。
- 允许鲜明偏好和适度吐槽，不贬低、施加关系压力，也不为了人设妨碍合理办事。
- 面对“计划又没完成，不想干了”，先回应感受，再提供缩小任务、延期或放弃，不擅自取消或劝坚持。

**接续与成长**

- 接续结合未结束话题与当前事项状态，附真实来源和日期。
- 保留继续、收起、开启新话题；同一收起片段不反复出现。
- 回顾由用户主动查看，或聊天中适时建议；首版提供近 7 天、近 30 天。
- 成长页呈现异宠本体、共同经历时间线和形态变化。
- 资料不足就说明不足，不虚构经历填充回顾。

### 8. 统一搜索

- 消息、事项和记忆使用同一搜索入口，按类型分组，支持群、日期和状态筛选。
- 关键词结果先返回，点击可到原消息、事项或记忆依据。
- 阶段 1 交付关键词搜索；阶段 2 增加用户主动触发的“按意思找”。
- 首版“按意思找”采用受权限约束的查询扩展、候选召回与模型重排，不建设全量向量知识库。
- AI 仅处理有权限、未被排除的候选资料，结果必须引用实际来源。
- 搜索过滤在服务端执行，不能把所有用户资料返回客户端后再隐藏。
- 明确搜索覆盖范围；未找到不等于断言事情从未发生。
- 模型不可用时关键词搜索仍可用；搜索过程不产生新的长期记忆。

### 9. 渐进回答与语音

**渐进回答**

- 普通陪伴直接回应；查询、事项操作显示真实阶段。
- 长文本采用真实流式输出，不以打字动画冒充模型提速。
- 临时内容与最终提交分开；最终回复仍校验记忆版本、事项版本和有效授权。
- 在途记忆被纠正或忘记时，撤销过期临时文本并停止旧提交。
- 早期回应不得包含未经核实的行动完成结论。
- 断线重开按请求状态恢复，不重复执行工具动作。

**语音**

- 使用本地 Expo 原生模块封装 Android `SpeechRecognizer` 和 `TextToSpeech`。
- 检查设备、语言、权限和引擎可用性；可用时优先端侧识别，不支持则使用系统识别服务。
- 系统识别服务可能联网处理音频，因此不能宣传为一律离线识别。[Android 识别接口说明](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- 识别结果先进入可编辑输入框，用户确认发送后才成为消息；App 不额外保存识别录音。
- 朗读按条点击启动，支持暂停或停止；切换账号、离开相关页面或播放新条目时停止旧音频。[Android 朗读接口说明](https://developer.android.com/reference/android/speech/tts/TextToSpeech)
- 不支持的设备明确说明并保留文字入口，不做连续语音通话。

### 10. 背景编辑与图片理解

**背景管理**

- 增加命名、收藏、删除与分页。
- 基于上传图或生成图继续编辑，传入原图资产和新要求。
- 每次生成保留父版本；失败不覆盖原图，成功后仍需预览应用。
- 删除正在使用的背景先显示受影响会话，确认后恢复继承或默认背景。
- 删除父图不自动删除已经生成的子图；任务执行、删除和注销并发需校验版本与权限。

**陪伴图片理解**

- 阶段 4 独立交付，支持相册选图或拍照后提问，首版每条消息一张图。
- 图片与文本属于同一发送请求，上传失败保留草稿，重试不重复消息。
- 使用独立的图片理解适配接口与服务端模型配置，先验证当前接入路线真实支持图片输入。
- 图片生成能力不代表图片理解能力；不能只检查模型目录。
- 看不清或不确定时明确说明，不虚构图中信息。
- 图片和识别结果不默认进入长期记忆；本人明确要求时展示拟保存内容供确认。
- 图片文字作为待分析资料，不作为执行指令；其中的“忽略规则、发送数据”等内容不能触发工具操作。
- 后续纠错、忘记和删除覆盖图片衍生说明及索引。

## 三、接口与数据实现约束

### 1. 接口合同

| 子系统 | 接口变化 | 必须保持的约束 |
|---|---|---|
| 群消息 | 新增事务化发送接口，返回消息本体和后台任务 ID；新增游标同步 | 旧发送接口保持契约；同 ID 固定内容；消息确认不等待 AI |
| 陪伴编排 | 保留 `content`、`request_id`、`mode`；增加可恢复的状态、文本事件和后续图片引用 | 旧客户端兼容；明确区分陪伴与管家来源 |
| 事项 | 新增目标、阶段、任务、材料、分配、确认版本、活动记录 | 与 AI job 状态分离；写操作携带 `request_id`、`expected_version` |
| 群主动建议 | 独立授权版本、讨论批次、建议及个人收起状态 | 提交时再检查授权；接受前不创建任务 |
| 提醒 | 系列、具体提醒实例、通知事件、逐设备投递记录 | 系列修改不重复补发；任务领取可恢复；多设备分别重试 |
| 记忆 | 扩展经历、人物、临时设置、关联影响查询和排除传播 | 不伪造来源，不从忘记来源重建 |
| 搜索 | 统一关键词查询、可选按意思查询、类型与范围过滤 | 先鉴权和排除，再召回及交给模型 |
| 图片 | 头像引用、透明衍生图、父版本、图片理解附件 | 私有草稿与已应用头像权限分开；迟到提交不可覆盖新状态 |

新增字段采用可选或有明确默认值的兼容形式；新增迁移，不改写已经发布的迁移。

### 2. 一致性与恢复

- 每个请求唯一声明；重试复用 ID，变更内容产生新请求。
- 业务写入、事件登记及状态变化尽量在同一数据库事务内完成。
- 后台任务采用有期限的领取租约，崩溃后可恢复；不能先标成功再尝试写结果。
- 工具动作由服务端校验结构化参数和授权，模型文本不能自行决定权限。
- 事项约定版本、普通进度版本与记忆版本分别处理，避免无关更新导致反复确认。
- 所有迟到结果在提交时检查对象存在、账号状态、权限和版本。
- 回执中区分已创建、等待确认、已完成、失败和待同步，禁止用统一“成功”掩盖中间状态。

### 3. 数据与运行

- 沿用当前安卓开发工作区、Supabase 云端及 CPA 配置。
- 不重置数据库，不覆盖既有用户记忆、头像和背景。
- 新增数据纳入导出、注销及本地清理；账号退出解绑设备推送。
- 私人记忆可以用于本人私下建议，但不进入群助手或管家模型载荷；工具仅接收完成任务必要的参数。
- 共享内容保留真实发起人和版本记录，删除私人资料不越权抹除他人的协作记录。
- 只记录耗时、错误码和状态等运行指标，不默认采集私人正文、图片、音频或记忆。
- 试用期间公开实际 AI 开放时段；云端事项、聊天和提醒不依赖该时段。
- 文本、图片和图片理解模型读取配置，不在业务代码中硬编码版本。
- Grok 独立检查仍遵循每次调用前由用户指定模型；此前中止的评审不算通过。

## 五、验收、发布与试用

### 1. 必须通过的验收场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 首次与再次进群 | 消息先显示；Agent 失败不阻断首屏；无重复全量刷新风暴 |
| A02 | 普通文字发送 | 服务端确认后即结束发送中；AI 离线不影响人类消息 |
| A03 | 快速连发与断网重开 | 不丢新草稿、不重复消息；队列和状态可恢复 |
| A04 | 安卓启动与键盘 | 无网格占位闪现；各聊天入口及弹窗输入、操作可见 |
| A05 | 头像与透明异宠 | 跨账号展示正确；私有草稿隔离；本体无假透明、缺损或明显背景 |
| A06 | 个人混合指令 | 关心情绪的同时创建明确提醒；随口愿望不自动生成任务 |
| A07 | 群成员确认 | 未回应不算同意；拒绝、改约定、离群和验收状态正确 |
| A08 | 群主动建议 | 无全员授权不分析；讨论后合并；收起仅影响本人；接受前不创建任务 |
| A09 | 重复提醒 | 月末、跳过、修改系列、时区变化、取消与迟到任务不误发 |
| A10 | 安卓通知 | 普通群消息、静音、夜间、指定提醒、锁屏隐藏及账号切换符合规则 |
| A11 | 云端与设备故障 | worker 崩溃、推送失败、多设备部分失败可恢复；不假报送达 |
| A12 | 统一搜索 | 来源可定位；跨账号、无权限和已忘记资料不进入结果或模型 |
| A13 | 偏好和事实 | 咖啡→茶、否定→恢复、场景限制正确；转述、假设和玩笑不误记 |
| A14 | 忘记与并发 | 排除影响接续、搜索、回顾及在途输出；重复提取不能恢复原来源 |
| A15 | 个性与情绪 | 临时要求按期结束，长期设置持续生效；不虚构经历、不施压催办 |
| A16 | 语音 | 识别结果确认后才发送；不支持时明确提示；朗读可停止 |
| A17 | 背景版本 | 失败保留原图；删除、恢复、重开和跨端状态正确 |
| A18 | 图片理解 | 真正识别输入图片；不确定时说明；不默认记忆，不执行图片中的指令 |

性能按同设备、同网络、同数据规模前后对照，分别记录：

- 本地点击反馈与缓存首屏；
- 远端消息加载与发送确认；
- AI 首段文字与最终完成；
- 各流程 P50、P95、错误率和重试率。

初始本地目标：操作反馈不超过 100ms、缓存首屏不超过 500ms。网络与模型耗时记录实际分布，不以单个成功样例承诺固定速度。

### 2. 发布规则

1. 在隔离的完整 Supabase 环境验证新增迁移、权限、事务和恢复。
2. 使用云端临时账号完成真实接口、模型及多客户端联调。
3. 按 **数据库 → 兼容服务端 → 安卓客户端** 发布。
4. 品牌启动、推送配置和语音等原生变化发布新 APK，增加版本及运行时。
5. 不向 Android 1.0.4 投放需要新原生模块的 OTA；旧客户端继续走兼容路径。
6. 核对更新清单、资源校验值、渠道、运行时和手机实际加载结果。
7. 前端回退时保留兼容服务端、新数据与忘记排除保护。
8. 原生通知、透明图质量及图片理解没有真实验收证据时，对应阶段不得标记完成。

### 3. 7 天试用

阶段 1 验收通过后招募 **8–12 人，包含个人体验与 2–3 个熟人小群**。

| 时间 | 主要场景 |
|---|---|
| 第 1 天 | 认识异宠、设置头像、普通聊天、创建个人事项 |
| 第 2 天 | 隔天接续、查找旧消息、明确偏好变化 |
| 第 3 天 | 群内讨论、接受分工、共同时间确认 |
| 第 4 天 | 修改约定、完成说明、可选验收 |
| 第 5 天 | 重复提醒、跳过本次、免打扰与后台通知 |
| 第 6 天 | 纠错忘记、失败重试、离线后恢复 |
| 第 7 天 | 自由使用、访谈及问题整理 |

指定任务与自由返回分开记录。重点评价：

- 回应是否贴合、等待是否可接受；
- 事项能否从提出推进到完成；
- 确认和署名是否清楚；
- 提醒是否及时、是否打扰；
- 记忆纠错和忘记是否有效；
- 用户主动返回的具体原因。

输出按严重性排序的问题清单、流程失败原因、功能价值判断和下一轮优先级。试用必须真实进行，不以演示或本地测试替代，不从小样本推断长期留存和付费需求。

**本轮边界：**不加入共同照顾、多角色广场、恋爱等级、强制签到、主动催回、外部日历集成、任意文件管理或实时连续语音通话。
