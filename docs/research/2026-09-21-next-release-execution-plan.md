# 异宠下一轮执行计划：安卓验收与免费云端验证

规划日期：2026-09-21。执行更新至 2026-09-22：**Android 1.0.9（11）验收包、两批异宠工作区与能力授权 OTA 已交付；云端统一执行链及陪伴格式修复已部署。真机、独立检查、正式放行与真实试用尚未完成。** 最新范围和证据见 [9 月 22 日交付记录](../implementation/2026-09-22-pet-workspace-capabilities-release.md)，原计划逐项状态见 [执行台账](../implementation/2026-09-21-next-release-execution-ledger.md)。

本计划补充 [9 月 11 日最终功能计划](./2026-09-11-feature-improvement-roadmap.md)，用于收尾当前版本和安排后续交付，不重新开发已有模块。当前发布事实以 [1.0.9 手机验收记录](../implementation/2026-09-21-android-1.0.9-device-acceptance.md) 为准；保留 [1.0.8 候选版记录](../implementation/2026-09-21-release-candidate.md) 和 [App 内云端更新记录](../implementation/2026-09-21-in-app-cloud-updates.md) 作为此前基线。用户仍从旧 App 发起更新。

## 一、已确认的安排

1. **安卓优先，Windows 后续补验。** Windows 的未完成项单独登记，不阻塞安卓修复。
2. **先用免费额度验证云端。** 不新增长期付费服务，不开通付费试用、不绑定信用卡；先核实可用资源和限制。免费资源不满足要求时提交测量结果与可选方案，不自动购买。
3. **从旧 App 取得更新。** 普通修复使用 OTA；涉及原生代码时，从 App 内发起新版下载，由 Android 系统确认覆盖安装。不要求卸载、不涉及 Google Play。
4. **先把现有功能完整验收。** 保留已认可的视觉、模块分工、主题与背景；本轮不再做一轮整体界面重设计。
5. **真实手机结果单独记录。** 用户暂不连接 USB，沿用手工清单；网页、编译、云端回执都不能替代手机显示、操作和推送结果。

- **第一批：N01 + N02，穿插 N03 核心检查。** 先确认旧 App 能收到更新，同时解决两个已知桌宠缺口。

不承诺未经测量的固定工期。手机反馈、免费资源实际可用性和多日观察分别登记，不能用“开发完成”替代这些依赖。

## 四、关键任务的执行细节

### N01：先把验收对象固定下来

- 保存当前工作区快照、依赖锁、APK 签名与哈希、原生 runtime、各 runtime 的 OTA ID、云端迁移/函数版本。
- 使用合成账号 A、B 和测试群；涉及多方共同决定时增加 C。第二客户端可用网页辅助，手机特有行为仍在手机检查。
- 台账使用：待执行、实现完成、自动验证通过、待真机、失败待修复、已验收。记录日期、版本、步骤、预期、实际、证据和负责人。
- 开发负责人处理实现、云端和自动化；用户按手机清单反馈；整合负责人判断是否通过。自动化代理可以分模块执行，共享迁移、类型和最终发布由同一负责人整合。

### N02：桌宠必须在其他 App 上可用

**草稿恢复**

- 当前风险是小窗只在关闭时保存草稿。改为随编辑持久化，并检查 Android 存储写入时机、主线程开销和异常退出的恢复边界。
- 草稿按账号、异宠和会话隔离；发送只清除该次提交的文本。正在发送时继续输入的新草稿保留。
- 保存带版本约束；退出账号/删除草稿后，迟到保存不能恢复旧内容。主动退出清理与进程被回收后的恢复分开处理。
- 验收覆盖输入后立即切页、强行停止并重开、断网发送、发送后继续输入、退出切换账号。分别测紧接最后一次编辑退出与停留后退出；若仍有丢失窗口，如实登记并继续修复，不笼统宣称“绝不丢失”。

**透明触摸**

- 先做 Android 系统窗口可触区域的最小验证：透明角落下方放置其他 App 的按钮，实测点击落到下层，同时主体仍可点开和拖动。
- 不能仅通过 ImageView 的触摸回调返回 false，就认定可以穿透到其他 App；不能借用 Windows 结论。
- 验证系统支持的实现与兼容范围。若某类设备无法满足，单列限制和可验证替代交互，取得明确产品决定后再改范围；不悄悄把“隐藏后能点”当成“显示时透明区穿透”。
- 隐藏、停止、撤销权限、退出账号都必须移除相关窗口；锁屏不展示私聊。不得通过新增无关高权限或模拟用户点击解决。

### N03：手机验收先短后全

先执行 [现有安卓手工清单](../implementation/2026-09-21-android-device-checklist.md) 的 U01 和 Q01–Q05，再分次做 D01–D13。N02 改动后补测未收起草稿恢复；保留旧版本失败记录。

通知增加以下独立记录：

| 情况 | 预期 |
|---|---|
| 手机后台、锁屏收到普通群消息与 @ | 在授权和设置允许的情况下实际出现通知，锁屏默认不暴露正文 |
| 正在查看对应会话 | 不重复响铃；看过的旧消息不恢复红点 |
| 逐群静音、夜间免打扰 | 按设置执行；不改写用户已有选择 |
| 用户明确设在免打扰时段的提醒 | 设置说明清楚，并遵守手机系统权限与勿扰设置 |
| 权限拒绝、令牌失效、无设备或部分设备失败 | 分别显示准确状态；不假报已送达，重试不重复提醒实例 |
| 点击通知、对象取消、账号切换 | 到正确消息/事项；无权限或已取消时说明现状，旧账号设备绑定清除 |
| CPA 和透明 worker 停止 | 普通群消息、云端事项与提醒仍可运行 |

若目标设备收不到推送，先分辨设备注册、云端投递、手机网络/服务能力及系统后台限制。修复后复测；必要的替代推送方案单独评估。不能通过要求测试者连接开发者局域网、展示云端成功回执或只测前台来代替通过。

### N04：提速以实测瓶颈为依据

保留已有事务发送和队列，测量以下时间：点击反馈、缓存首屏、人类消息入库确认、后台排队、授权与资料查询、模型首段、模型完成、最终校验与写回。

- 分别测普通群消息、群 @、个人陪伴、陪伴查群消息、桌宠小窗；区分冷启动与连续使用，不用主人身份快答代替普通生成。
- 当前云端普通消息 8 个样本 ACK P50 174ms、P95 232ms 只作历史观察；真实群模型样例约 7.8–15.6 秒、Windows 小窗完整回复约 15.6–35.2 秒说明 AI 路径仍需优化，不能混成同一个延迟指标。
- 第一轮每类收集至少 20 个合成请求作为排查样本；可见改善后对受影响路径按冷/热条件补充样本，再做前后对照。报告样本数和分布，小样本 P95 仅作观察，不承诺总体水平。
- 保持原计划的本地目标：操作反馈不超过 100ms、缓存首屏不超过 500ms。网络与模型先据实测定，再制定发布门槛；超时、重试率和回答质量必须一并比较。
- 优先处理重复查询、可以安全并行的请求、无必要的模型往返、过多上下文及转发缓冲。缓存仍须校验账号、权限、来源排除和版本；不为提速使用已忘记资料。
- 真流式需贯通提供方、网关、服务端和手机。先出现“正在处理”不算首段文字；停止、断线恢复、在途纠错要撤销旧文本并阻止旧回复提交。
- 不自动替换业务模型。若需比较模型，先明确候选和试验范围；涉及 Grok 时每次调用前由用户指定模型。

### N05：免费云端验证分两份结论

现有 Supabase 数据库、群消息、事项与提醒继续复用；不重复迁移，也不重置数据。

**A. 模型网关**：核实当前 CPA 的运行、凭据/登录状态持久化、上游访问、流式转发及重启恢复能否在候选环境成立。把网关搬到云端并不提供免费的模型额度，也不保证模型推理更快。优先复用现有合法可用额度；无可用额度时如实阻塞，不开通新付费调用。

**B. 透明 worker**：测量模型加载、峰值内存、磁盘、CPU、单图耗时和冷启动。继续使用固定依赖的 rembg 及显式 isnet-general-use，核对模型文件校验值；不换成生成式重绘。不因模型文件只有约 179MB 就推断总内存够用。

候选资源先核对官方当前条件：是否必须绑卡、地区与访问、免费时长/额度、休眠、后台进程、内存/存储、出网、持久盘、秘密管理、上游服务使用条件。当前不指定未经核实的平台，也不把“能启动一次”等同“免费常驻”。

交付物与通过条件：

1. 每个服务分别给出资源测量、候选对照、部署配置、凭据保存方式及免费额度不足时的停止策略；日志仅含必要运行指标。
2. 先用隔离测试配置或限定测试账号跑真实请求，再切换经过验证的正式路径；不边试边覆盖所有用户的网关地址。
3. 网关真实文本/图片路由与透明任务的领取、处理、云端保存、本人预览确认按各自功能验收；验证崩溃后租约恢复和同任务不重复应用。
4. 在受控测试中停止开发电脑对应服务，云端仍能完成任务。无需关闭用户整台电脑或改动无关服务。
5. 建议至少连续观察 24 小时，包含空闲后的首次请求、服务重启和配额接近限制时的行为；这是本轮验证条件，不是长期可用性承诺。
6. 回退保留任务 ID、来源排除和数据；旧/新 worker 不抢占同一有效租约。超额或资源不足时明确排队/不可用，不循环消耗额度。

结论分别填写“可在本轮试用条件下持续运行”“仅适合临时验证”“不满足”。如果免费资源不能持续运行，可以继续修复安卓，并沿原计划在公开 AI 可用时段内试用；此时 N05 只能标记可行性验证已完成，**云端常驻目标未完成**。不把临时方案说成正式长期部署。

### N06：复用代码，验收两条完整流程

**个人流程**：明确指令或接受建议 → 目标/阶段/任务 → 可空日期与提醒 → 完成/延期/放弃 → 有来源的查询和回顾。混合情绪与办事需同时处理；愿望不能自动创建；离线个人修改显示待同步，冲突不覆盖云端新版本。

**群流程**：私人预览 → 本人确认代发与署名 → 负责人接受/拒绝 → 必要成员确认约定 → 进度 → 完成/可选验收。沉默不算同意，普通进度不触发重新同意，改约定需新版本，离群使未完成确认失效。

补验重点：未全员授权不主动分析、授权后合并建议、撤回后的迟到任务、同请求重试、资料删除/账号退出、跨账号隔离、个人记忆不进入群模型。忘记传播到搜索、接续、回顾、性格来源和在途文本；原会话可回看不触发重新提取。

### N07–N08：分模块收尾，保持各自开放条件

- **透明本体**：准备毛发、细装饰、多附肢、半透明部位的合成或获授权样本，逐张在深浅背景和手机悬浮检查。保留原图和失败结果；假透明、缺损、明显脏边不通过。此项属于桌宠可用性的必要检查，优先于其他后续图片能力。
- **性格与关系**：至少跨 3 天观察明确偏好、临时语气、长期习惯及反向变化；结合后续 7 天试用。记录能否追溯来源、及时纠正、保持主人绑定；不能将单句话贴成长期性格标签，不能推断未表达的私人关系。
- **语音**：实际检查识别引擎、权限拒绝、结果先入草稿、用户发送、朗读停止与账号切换。设备不支持时说明并保留文字入口。
- **背景与原图编辑**：先验现有命名/收藏/删除/分页及跨端状态；再用真实模型验证父版本引用、保真、失败保留原图、删除/生成并发。未通过原图编辑保真前保持对应开关关闭。
- **图片理解**：实际图片经 App、上传、服务端到独立视觉模型完成全链路，覆盖模糊图、不确定回答、图中文字指令、确认记忆与忘记。每条一张图，上传失败保留草稿；不能用图片生成或单次直接模型探测替代。
- **Windows**：后续补旧版覆盖升级与资料保留、实际安装后的登录悬浮、锁屏/休眠、多显示器/缩放；安装向导及未签名提示如实说明。沿用已通过的基础安装/卸载证据。

后续语音、图片编辑、图片理解及 Windows 的独立开放不阻塞已通过的安卓核心修复。已开放功能若发现隐私、数据丢失或重复执行问题，必须修复或明确停用受影响入口后重新验收，不能仅记为普通已知限制。

## 五、验收、更新与试用

### N09：审查和发布

独立检查按范围拆开：消息/已读/账号清理；桌宠原生生命周期；记忆与事项版本/授权；云端网关与 worker；更新兼容。每次 Grok 调用前重新由用户指定模型；超时和中止均无通过结论。主负责人用实际代码及验证处理意见，记录采纳、修复或有证据的不采纳原因。

发布分两类，可独立推进：

| 类型 | 方式 | 必须核对 |
|---|---|---|
| JS、布局、业务逻辑或兼容服务端修复 | 已有 runtime 的 OTA；服务端按兼容顺序部署 | 旧 runtime 能接收、资源哈希、手机实际 OTA 标识、停止/恢复和隐私不回退 |
| 桌宠 Kotlin、原生权限或配置修复 | 尽量合并一次原生升级；构建时分配递增版本和 versionCode | 原包名与签名、APK 哈希、旧 App 内下载入口、系统确认、覆盖保留资料、新 runtime 的 OTA |

当前原生更新入口是从 App 打开已核验的 APK 下载，由浏览器/系统接管；尚不等于 App 自行下载字节、显示进度或静默安装。发布不能把“已打开下载”记成“更新完成”。

下一版更新已批准的 APK 元信息时，必须同步旧 runtime 的兼容入口与云端发布清单，验证它们接受同一份新版本；不能只替换清单而让客户端仍固定接受旧 APK。

发布顺序仍为数据库（如有新增）→ 兼容服务端 → 对应客户端。保存准确源码快照和收据；失败可回退界面，但保留兼容服务端、新数据及忘记保护。普通 OTA 不为凑版本号构建 APK。

**安卓阶段 1 试用准入条件：**

- 从原 App 更新、核心聊天/输入、头像/未读、已开放桌宠与透明形象通过真机验收。
- 个人及群事项完整流程、目标设备真实通知、失败恢复、权限和记忆排除通过；未测通知不算通过。
- 关键缺陷归零：跨账号暴露、忘记后复用、重复业务动作、数据丢失、无法完成主要流程均阻塞对应发布。
- AI 可用路径、开放时段、错误状态和实际耗时有记录。免费云端未成立时明确保留现行运行限制，不假报常驻完成。
- 此次变更的独立检查与必要回归完成；原图编辑/图片理解等未验证功能保持关闭，试用材料如实列明范围。
