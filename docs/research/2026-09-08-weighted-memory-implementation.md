## 2. 实际行为

### 表达证据 → 当前偏好 → 本轮相关记忆

每条自动证据保存本人来源消息、发生时间、对象、主题、场景、肯定/否定、过去/当前、表达强度和原话；来源、对象、极性、时态、操作共同去重。模型提供候选后，还要通过结构校验、原文匹配、本人表达与语境校验。假设、引用他人、问题、玩笑及不确定表达不直接入库。

同一对象和场景的最新有效当前表达决定当前状态。权重只排序有效偏好，不投票判断事实。手工保存的事实与经历保持独立，不补造提及次数，也不强行转成喜好。

| 表达/操作 | 结果 |
| --- | --- |
| 我以前喜欢咖啡，现在更喜欢茶 | 保留过去的咖啡，当前优先茶；不推断从来不喜欢咖啡 |
| 我已经不喜欢咖啡了 | 咖啡停止当前推荐，历史肯定仍保留；以后明确喜欢可恢复 |
| 你记错了，我从没喜欢过咖啡 / 纠正 | 错误依据无效，不再当成真实过去；可在依据记录中核对失效状态 |
| 忘记某项偏好 | 停止使用对应依据及已关联来源、派生回复和风格摘要；原消息可回看，原任务不能再提取恢复 |
| 晚上不喝咖啡 | 只约束晚上；当前使用显式场景匹配，不凭用户所在地时间自动推测场景 |
| 编辑手工记忆 | 保留旧版本供本人核对，模型使用当前版本，继续原话题 |

含糊的“忘记这件事”不让模型假装操作成功，会引导用户在记忆卡片中确认对象。第一批聚焦中文明确偏好与相处方式；复杂代词指代和人物关系不在本批自动提取范围。

### 可解释排序

通过状态、话题、场景筛选后，默认分数为：

`0.5 × 2^(-距最近表达天数/30) + 0.3 × min(近90天有效表达天数/5, 1) + 0.2 × 表达强度`

频次按 UTC 自然日聚合，同对象同日最多一次；普通明确喜欢强度为 0.6，强烈或更偏爱为 1。手工标记喜欢/不喜欢不增加“对话表达天数”。明确否定和明确比较优先处理，标记重要不会覆盖否定或无关场景。每轮最多选择 5 项相关自动偏好，手工 20 条限额独立。

规则集中在 [preferenceMemory.ts](../../supabase/functions/_shared/preferenceMemory.ts)。初始系数在该共享模块配置；SQL 中 90 天窗口与之保持一致，调整窗口时必须同步迁移和验证。界面显示“最近明确表达过”“近 90 天有几天表达过”等解释，开发数据保留计算因素和分数。

### 连续性、纠错与重试

记忆操作递增版本，但不修改话题起点。模型生成后以同一只异宠的锁和版本校验提交；期间发生变更会拒绝旧回复。客户端保存同一请求标识，重试复用已写的主人消息，成功后清除草稿。若原来源已被忘记或用户已另开话题，界面说明后下一次发送使用新请求。

回复记录用了哪些来源、自动依据和手工记忆。忘记/纠错从来源出发，传递排除消费过这些内容的回复；有来源的风格摘要也失效。迟到的后台摘要插入需要通过数据库来源检查。原始聊天仍可回看，不会因为修改一条喜好而清空所有无关主人发言。

当前采用整条来源消息作为最小排除粒度：一条消息里同时说咖啡和面试，忘记其中咖啡可能连带排除该消息的面试内容。已经依赖受影响回复的后续回复也会被排除，这是本版较保守的来源边界。跨消息、未关联的原始主人发言仍可继续使用。

旧版没有来源关联的模型风格推断和异宠回复不装配进新的私聊上下文；既有手工条目仍保留。新增个人记忆及偏好不接入群发言和形态进化。既有成长记录不是本轮新增记忆，当前不承诺抹除全部历史成长痕迹。

提取在私聊回复成功后后台运行，异常不隐藏回复。任务以租约保护，每批最多 3 个、单轮最多 3 次尝试；后续成功聊天会处理待办，失败任务可由本人按钮重新排队。没有额外配置定时扫描。配额按账号记录，避免无边界重试。

另增“当前否定覆盖旧偏好”和“偏好变化后接回面试项目”两个真实模型场景。第一轮能接续，但项目辅导中出现未提供的问卷数字示例和动机推测；已明确只用原有事实、未知行动和结果待补充，并要求默认简短、只问一个关键缺口。本轮中途还观察到一次 `text_model_timeout`，保留标准化错误，未放宽超时或伪造回复。完整真实模型链路的首次运行也遇到非法 JSON；清理该轮合成账号后重新运行 5 组全部通过，成功轮未触发错误恢复。这不代表模型已长期稳定；失败重试另用可控故障在实际 Edge 链路中验证。

最终单独复测“偏好变化后接回原话题”，回应先说“现在茶更合你的口味”，继而引用已有问卷发现，把改进行动和效果标为待补充，只提出一个问题；没有再给出虚构数字或声称后台已保存记忆。这是单个真实样例的人工核对结果，不代表所有对话都能稳定遵守约束。
