## 当前资源测量

模型网关为现有 Windows CLIProxyAPI，端口 8317。只读取配置结构和进程指标：有 3 份持久登录文件、2 组兼容 API 配置；没有复制凭据到测试文件或云端。一次进程观测工作集约 68 MiB、峰值约 112 MiB，后续工作集约 77 MiB。它是已有长时间运行进程，不能当作冷启动或云端内存保证。凭据续期写回、上游授权能否用于云端托管、Linux 重启恢复和受限网络访问尚未验证。

透明 worker 使用当前锁定的 Python 3.13、rembg 2.0.67 和 `isnet-general-use`。模型 178648008 字节，SHA256 `60920e99c45464f2ba57bee2ad08c919a52bbf852739e96947fbb4358c0d964a`。对已有获准使用的合成毛发样本启动三次独立处理子进程：

| 1 | 33.24 秒 | 30.50 秒 | 0.65 秒 | 0.78 秒 | 1.86 GiB |

每次重新建进程，操作系统磁盘缓存未受控。不是三次完全相同的冷启动，也没有模拟免费云端 0.1 CPU。首次导入明显较慢；不能只测 ONNX 文件或推理函数来估算服务资源。三份结果 SHA256 均为 `96ae7d0045bbbcb0ea093af68a2e2713aa8886206eea2180a141bb477fb7345d`，与已有合成样本一致，不代表多样本质量通过。

测量脚本：`scripts/profile-transparent-worker.py`；完整数据与输出：`test-results/next-release-worker-profile-20260921/`。没有领取生产任务，子进程不携带云端秘密。这些是本机实际测量，Linux 内存上限仍需要目标环境验证。

## 两份结论与尚缺证据

- **网关：仅适合进一步临时验证，当前没有已经验证可持续运行的免费部署。** 内存观测不是主要排除项，休眠、磁盘、已有登录状态、上游使用条件和可访问账号仍未解决。搬迁网关不会提供新模型额度。
- **透明 worker：本轮已核查的可访问免费候选不满足直接迁移条件。** 这不是“所有免费服务都不可能”的结论；本机约 1.5–1.9 GiB 峰值已经足以否定“179 MB 模型可直接放进 512 MB”的假设。

后续若取得既有免费资源，先部署隔离配置：保持原模型和依赖锁；使用平台秘密存储及受限 worker token；网关登录状态必须有可验证的安全持久化。先验证单账号真实文本/图片请求、透明任务 lease→处理→私有存储→本人确认、崩溃租约恢复与重复提交，再进行停本机对应服务测试及至少 24 小时观察。当前这些项目全部未执行。

没有资源时继续使用已公开说明的本机在线限制；不足、限额或休眠时明确排队/不可用，不循环保活、不自动加购或切换所有用户地址。没有正式迁移，因此本轮无需回退地址或抢占任务租约。
