# 自己恢复 AI：不用重新安装 App

CPA 和公网隧道是两个程序。CPA 在你的电脑上提供模型，隧道让 Supabase 云端能访问它。只打开 CPA、没有隧道，手机仍会显示 AI 离线。

## 日常启动 / 离线后重启

1. 先打开 CPA，确认它使用 `127.0.0.1:8317`；如果平时依赖网络代理，代理也要保持运行。
2. 在本项目文件夹双击 **启动AI隧道.cmd**。首次使用或重新登录时可能稍慢。
3. 等待看到绿色提示：**[4/4] AI 已恢复：云端文本接口在线，图片接口在线。**
4. 手机退出异宠页再进入；如提示仍未刷新，关闭 App 后重新打开。
5. 电脑、CPA 和启动窗口保持运行，窗口可以最小化。不要让电脑休眠。

脚本会自动读取本机 CPA 配置、重启本项目的旧隧道、获得新的公网地址并同步到云端，不需要复制地址、填写 API Key、发布 OTA 或重装 APK。

想放到桌面时，请给 **启动AI隧道.cmd 创建快捷方式**，不要单独复制或移动这个文件，因为它需要同目录中的 `scripts` 文件夹。

也可以在项目文件夹打开终端执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\restart-demo-ai.ps1
```

## 常见提示

- **Supabase 登录不可用**：在终端运行 `npx supabase login`，按提示登录当前项目的 Supabase 账号，再双击启动入口。不要把访问令牌或 API Key 发给别人。
- **CPA 当前不可用或密钥无效**：检查 CPA 是否启动、端口是否为 8317。当前默认配置读取 `D:\CLIProxyAPI\config.yaml`。
- **未找到 cloudflared / Node.js**：这台电脑已经安装；换电脑时需要另外安装，不能只复制脚本。
- **本机未完成公网探测**：当前入口随后会从 Supabase 云端验证真实连接。以最后的绿色成功提示为准；如果最后报失败，则没有完成恢复。
- **进程身份已变化，未停止任何进程**：安全保护阻止误关其他程序。先保留错误与日志，不要按任意进程 ID 手动结束程序。
- **窗口长时间没成功或云端仍离线**：检查网络和 CPA，再重新运行入口；不是重复安装手机 App。

日志位置由 `supabase/.temp/model-tunnel.json` 中的 `stderr` / `stdout` 字段给出。日志按启动时间分别保存，不覆盖上一次诊断信息。脚本不输出模型密钥；临时 Secrets 文件用完自动删除。

## 停止

双击 **停止AI隧道.cmd**。脚本只停止本项目记录且进程身份一致的隧道，不会关闭 CPA 或其他项目的隧道。

停止后，人类聊天、邀请和历史消息仍可用，只有 AI 查询、回复与生图不可用。这不是开机自启服务；重启电脑或隧道退出后，重新执行上述步骤即可。

云端检查只验证两个接口的可达性及鉴权；模型上游限流、余额或某一次生成失败仍可能导致单次请求报错。
