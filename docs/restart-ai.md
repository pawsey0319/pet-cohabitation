# 自己恢复 AI：不用重新安装 App

CPA 和公网隧道是两个程序。CPA 在你的电脑上提供模型，隧道让 Supabase 云端能访问它。只打开 CPA、没有隧道，手机仍会显示 AI 离线。

## 日常启动 / 离线后重启

1. 先打开 CPA，确认它使用 `127.0.0.1:8317`；如果平时依赖网络代理，代理也要保持运行。
2. 在本项目文件夹双击 **启动AI隧道.cmd**。首次使用或重新登录时可能稍慢。
3. 等待看到绿色提示：**文本试调用通过；图片模型目录可达，图片生成尚未验证。** 文本检查需要实际生成响应，可能比以前稍慢。
4. 手机退出异宠页再进入；如提示仍未刷新，关闭 App 后重新打开。
5. 电脑、CPA 和启动窗口保持运行，窗口可以最小化。不要让电脑休眠。

脚本会自动读取本机 CPA 配置、重启本项目的旧隧道、获得新的公网地址并同步到云端，不需要复制地址、填写 API Key、发布 OTA 或重装 APK。

想放到桌面时，请给 **启动AI隧道.cmd 创建快捷方式**，不要单独复制或移动这个文件，因为它需要同目录中的 `scripts` 文件夹。

也可以在项目文件夹打开终端执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\restart-demo-ai.ps1
```

## 常见提示

- **CPA 已开启，却提示“云端仍未连通 AI”**：2026-09-09 修复过检测脚本遗漏临时账号资料的问题。旧脚本会在文本调用前触发数据库外键错误，却把它统称为连接失败。修复后会初始化检测账号资料，并分别显示文本试调用和图片目录结果。已在原隧道上验证通过，无需重装 App。

- **Supabase 登录不可用**：在终端运行 `npx supabase login`，按提示登录当前项目的 Supabase 账号，再双击启动入口。不要把访问令牌或 API Key 发给别人。
- **CPA 当前不可用或密钥无效**：检查 CPA 是否启动、端口是否为 8317。当前默认配置读取 `D:\CLIProxyAPI\config.yaml`。
- **未找到 cloudflared / Node.js**：这台电脑已经安装；换电脑时需要另外安装，不能只复制脚本。
- **本机未完成公网探测**：当前入口随后会从 Supabase 云端验证真实连接。以最后的绿色成功提示为准；如果最后报失败，则没有完成恢复。
- **进程身份已变化，未停止任何进程**：安全保护阻止误关其他程序。先保留错误与日志，不要按任意进程 ID 手动结束程序。
- **窗口长时间没成功或云端仍离线**：检查网络和 CPA，再重新运行入口；不是重复安装手机 App。

日志位置由 `supabase/.temp/model-tunnel.json` 中的 `stderr` / `stdout` 字段给出。日志按启动时间分别保存，不覆盖上一次诊断信息。脚本不输出模型密钥；临时 Secrets 文件用完自动删除。

隧道仍在运行时，可仅重做云端检查，保留当前隧道和地址：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\restart-demo-ai.ps1 -CheckOnly
```

“已按启动流程跳过本机公网回环探测”是流程说明，表示随后从云端验证，不表示 CPA 未启动。检测临时账号及资料在检查结束后删除；原有用户资料不受影响。

## 2026-09-14：透明异宠处理

本机已经配置独立透明处理进程。正常执行“启动AI隧道.cmd”时，会顺带检查并恢复该进程；只检查连接的 `-CheckOnly` 不启动它。已在运行时不会重复启动。

也可单独恢复透明处理，不重启模型隧道：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-pet-transparent-worker.ps1
```

透明处理不调用文本或图片生成模型，而是使用固定校验的 `isnet-general-use` 分割原图。云端保存任务和结果，电脑只处理已获授权的图片。完成后在新版陪伴页“透明效果”中预览，点击“使用此透明效果”才会替换本体；失败或不满意时保留原图。

凭据使用 Windows DPAPI 保存在本账号 LocalAppData，不需要复制到聊天或命令参数。当前已验证的 Python 环境和模型保存在本机临时目录；若被系统清理，启动脚本会明确报错，需要恢复环境。它尚不是开机常驻服务。

## 停止隧道

双击 **停止AI隧道.cmd**。脚本只停止本项目记录且进程身份一致的隧道，不会关闭 CPA 或其他项目的隧道。

透明处理是独立进程，停止模型隧道不会停止它；电脑关机后，已有透明结果仍保存在云端，新任务等待下次启动处理。

停止后，人类聊天、邀请和历史消息仍可用，只有 AI 查询、回复与生图不可用。这不是开机自启服务；重启电脑或隧道退出后，重新执行上述步骤即可。

云端检查会真实调用文本模型并校验结构化响应；图片检查只验证鉴权和配置的模型是否在目录中。某次检查成功不能保证后续每次生成都成功，图片是否能生成仍需实际生图验证。

2026-09-08 已修复“显示在线但文本 HTTP 400”：原文本路由返回缺少会话标识的错误，而旧检查只请求模型目录。当前默认文本路由为已验证可用的 `glm-5.3`；重启脚本沿用这一默认值，显式配置仍优先。App 本次检查失败时不再展示历史成功记录。

2026-09-14 的群内回复与私人群消息查询各自使用可选云端配置 `GROUP_TEXT_MODEL`、`RECALL_TEXT_MODEL`，当前均为已验证的 `glm-5.3(low)`，普通 `TEXT_MODEL` 保持原值。重启隧道不会清除这两个额外配置；将来更换文本提供方时应同时核对它们。删除某一专用配置会让对应调用沿用 `TEXT_MODEL`，无需回滚权限、记忆排除或请求去重修复。查询的真实效果与耗时见[私聊群消息查询验收](implementation/2026-09-14-private-group-recall-timeout.md)。
