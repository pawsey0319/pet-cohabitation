# 异宠共生空间

一个面向恋人、好友和 3–8 人密友圈的本地纵向原型：每位主人终身拥有一只成长型异宠。异宠可进入多个熟人关系空间，但具体人物、事件、对话和记忆严格留在对应空间中。

## 产品定位与边界

原型包含双核心首页、关系空间与异宠生命档案，演示：空间记忆隔离、确定性的离线本地模拟、宠物角、空间主 Agent、低风险代理、照顾、可追溯记忆、身份锚点不变的渐进进化、可配置的“今晚碰个面”、带上下文的消息和安全共同游戏。

演示 seed 有三种关系空间，进入的始终是同一只异宠“灯灯”：

| 空间 | 类型 | 成员 | 示例语境 |
| --- | --- | --- | --- |
| 老友小圈 | 好友双人 `friend_pair` | 梅、林 | 周末接力游戏 |
| 海边二人间 | 恋人双人 `lover_pair` | 梅、雨 | 看潮汐 |
| 周末小队 | 三人好友圈 `friend_circle` | 梅、林、乔 | 三人同题揭晓 |

它不提供陌生人发现、公开动态、办公协作、文件传输或支付；内容按 16+、全年龄友好演示。异宠不会死亡、饥饿、退化或责怪长期未上线的主人，也没有经验条、亲密度、换宠、重抽或购买进化结果。

## 架构与本地模拟

这是 Expo 57 + React Native + TypeScript 的本地优先单客户端原型。

- `src/domain/` 是唯一领域类型来源，包含访问/代理策略、进化规则、三空间 seed 与确定性 Agent 运行时。
- `src/state/AppState.tsx` 用 reducer 管理状态，以 AsyncStorage 的 `pet-cohabitation-mvp-v1` 保存本机演示快照；hydration 完成前拒绝用户写操作，并由可访问的载入界面阻止主 UI 交互。
- 读取旧快照时会把持久化数据视为不可信输入：保留有效的嵌套记录、过滤/规范化无效项，并重新执行代理、成员、来源、回复和空间边界规则；写入按队列串行化。
- 若持久化 payload 损坏或被修复，原始 JSON 会尝试保存在本机隐藏键 `pet-cohabitation-mvp-v1-invalid-backup`，而 UI 只使用规范化后的状态。它不是用户可见的恢复功能，也不是云备份；生产保留期、导出、审计与过期策略尚未定义。
- `src/state/selectors.ts` 集中进行当前身份的空间、记忆、代理事项与宠物角可见性过滤。`src/screens/` 和 `src/components/` 只通过 provider action 修改状态，不直接改写 seed。

所谓“Agent”是确定性本地模拟器：不会联网、调用模型或在应用关闭后运行。离线模拟仅产生受上限约束的演示消息/宠物角故事；异宠邀请、空间总结、游戏主持和代理卡同样都是本地确定性结果。

`currentUserId` 是可持久化的本地演示状态，不是认证凭据，也不是不可伪造的当前用户。它只用于演示当前成员可见内容和可执行操作；生产必须以真实会话和服务端授权替代。异宠作息/离线模拟与仪式的默认时间处理为了可测试而使用 ISO/UTC 和手动填写的时区文本，尚无按用户或按空间执行的真实时区/提醒调度。

## 运行环境

- Node.js 20 LTS 或更高版本
- npm 10 或更高版本（Node.js 安装包通常自带）

在仓库根目录执行以下精确命令：

```bash
npm install
npm run web
npm test -- --runInBand
npm run typecheck
npx expo install --check
npm run export:web
```

`npm run web` 启动 Metro 开发服务，终端会输出浏览器地址。`npx expo install --check` 仅检查当前依赖与 Expo SDK 的兼容性，不升级依赖。`npm run export:web` 会生成本地 `dist/` 静态 Web 导出；`dist/` 不纳入版本控制。

## 390 × 844 演示步骤

1. 执行 `npm run web`，在浏览器开发工具设定 **390 × 844** 视口，打开终端输出的 Web 地址。短暂载入“正在载入本机共生档案…”后，才可操作主界面。
2. 首页确认“关系空间”为 3，并能看到老友小圈（好友双人）、海边二人间（亲密搭档）、周末小队（朋友小圈）；灯灯的名字、眼睛和声线在所有空间保持一致。
3. 在“今晚碰个面”填写合法 `HH:mm` 时间和时区文本，切换每天/每周，点“保存设置”；点“请灯灯邀请”，再切入目标空间，确认消息明确写为邀请、**不确认任何人的真实见面**。回首页点“关闭”，确认只关闭这项本地邀请设置，不发送取消通知也不调度提醒。
4. 从首页进入老友小圈，并切换顶部空间 tab 到海边二人间和周末小队：每个空间只显示自己的历史、记忆/宠物角语境和成员名，不显示另一个空间的具体内容。三者均为灯灯进入。
5. 在老友小圈输入一条消息，点“引用最近消息”“心情”和“意图”后发送；确认引用、心情、沟通意图与来源都显示在该消息上。再点“图片占位”“短语音占位”，它们必须显示“本地演示占位 · 未上传”，不是上传成功提示。
6. 在“共同造游戏”依次点“同题揭晓”“猜测选择”“接力”。每次都应在当前空间生成成员素材、异宠素材和空间主 Agent 的游戏主持输出；这里只组合预设安全素材，不执行任意代码。
7. 在同一空间检查三类内容（成员消息、异宠主观回顾、空间主 Agent 客观/主持输出）、宠物角和照顾；创建“暂定提醒”后依次点“本人确认”“撤回”。请求真实见面只显示阻断原因，不能代替主人承诺。
8. 点底部“异宠”，检查全局/空间记忆的来源、时间和可见范围；编辑或删除一条自动记忆。输入期待/祝福并点“交给灯灯决定”，再点“接受灯灯的成长”：主人只浅参与，不能选择最终形态。
9. 在主人生命档案底部，点“删除本机演示数据”后应先出现确认/取消；在单独演示会话点“确认删除”，当前消息、记忆与成长记录会恢复为确定性 seed。该操作只处理这台设备上的主原型快照，且确认后会重新保存一份新 seed；它不代表云端删除、远端备份删除或生产保留策略。

## 隐私、删除与记忆边界

- 具体记忆带空间 ID、来源与时间。异宠进入空间时仅可读取该空间记忆和非事件性的抽象特征；跨空间的人物、事件、对话、引用预览和回复目标都应被策略层拒绝或清除。
- 普通成员只看见其共同空间中允许公开的普通记忆；全局、主人专属、敏感与其他空间内容不可见。成员可照顾/提问，但不能更改异宠身份、全局记忆、成长档案或重大进化。
- 自动记忆可由主人编辑/删除。两步“删除本机演示数据”仅能由演示中的主人身份发起：先确认，再删除主本地快照并恢复/持久化新 seed；它不会删除不存在的云端账户或真实数据。
- 原始无效/被修复 payload 的隐藏本地备份与主本地快照是不同键。它不在 UI 中展示，且当前原型没有承诺其删除、导出或保留期限；生产环境必须另行定义最小化、保留、审计、导出和彻底删除策略。
- 本地浏览器/设备存储不等同于端到端加密；请勿把演示数据当作真实私密通信数据。

## 免费与收费边界

当前原型没有账户、订阅、内购、支付 SDK 或支付流程。产品设想中，异宠的基础生命、照顾、聊天、空间加入/退出、历史访问与数据导出应永久免费；不得对维持健康、避免死亡、第二只异宠或直接购买进化结果收费。任何未来会员能力（如生成额度、记忆容量、主题、高级 Agent 或游戏组件）均未在本仓库实现。

## 已知限制（请勿当作生产能力）

此仓库是 **local vertical prototype**，明确未实现以下能力：

- 云端异宠自主运行、跨设备同步、多用户网络、真实多人会话或服务器端消息历史；
- 真实认证、不可伪造的 `currentUser` / `currentUserId`、服务端授权或可信成员身份；
- 生产级端到端加密（E2EE）、密钥轮换、机密云执行或安全密钥恢复；
- push 通知、后台作业、日历/系统提醒或真实时区调度；
- 真实图片或短语音上传、媒体存储、音视频基础设施与文件传输；
- 真实模型调用、推理、训练、生成式图像或任何模型能力/效果承诺；
- 支付、订阅、内购、订单处理或收费执行；
- 云端数据删除 API、生产备份、备份保留期、导出与合规审计。

“图片占位”“短语音占位”“灯灯邀请”“空间主 Agent 游戏主持”和 invalid backup 都只是可审查的本地演示边界：前两者不会上传，邀请不会确认见面，主持不会执行任意代码或调用模型，backup 不会同步也未定义生产保留期。不要将这些界面或本地状态当作生产可用能力。
